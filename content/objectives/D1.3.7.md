## Azure first

- An **Azure role assignment** (principal + role + scope) is what gives an identity power over resources. Over time these pile up.
- **Defender CSPM** is the paid posture plan of Defender for Cloud. Its **CIEM** extension (cloud infrastructure entitlement management — "who can do what, and do they use it?") compares what identities *may* do with what they *actually* do.
- **Privileged Identity Management (PIM)** turns a standing role into an *eligible* one that is activated for a few hours when needed. It needs **Microsoft Entra ID P2** (or Entra ID Governance).
- An **access review** asks named people to confirm or deny each assignment, then can remove the denied ones automatically.

See the Foundations pages listed above, especially *azure-rbac-and-entra-roles*.

> **Licence note:** CIEM works on a Defender CSPM trial in your own subscription. **Access reviews and PIM need Entra ID P2** — treat those parts as a portal tour (screenshots below).

## In one sentence

You find overprivileged access with **Defender CSPM's CIEM recommendations** (overprovisioned and inactive identities) plus Defender for Cloud's identity recommendations (too many owners, guests or blocked accounts with rights), confirm it with **PIM access reviews**, and fix it by removing, narrowing, or converting assignments to **PIM-eligible**.

## Why it exists

Access is granted in a hurry and removed never. A contractor who needed Owner for a week still has it a year later. You know from incident work that a dormant privileged account is an attacker's favourite: high power, nobody watching. This objective is the clean-up routine — and the habit that stops the pile growing back.

## What actually matters

**1. The kinds of overprivilege.**

| Kind | Example | Found by |
|---|---|---|
| Excessive standing scope | Owner on the subscription; needs Contributor on one RG | CIEM *overprovisioned identities*; IAM review |
| Inactive (dormant) | assignment unused for 90+ days | CIEM *inactive identities* |
| Too many owners | 37 Owners on a subscription | *A maximum of 3 owners should be designated for subscriptions* |
| External/guest with rights | guest with Owner | *Guest accounts with owner permissions...*, *External accounts with owner permissions...* |
| Dead accounts still assigned | disabled or deleted users | *Blocked accounts with owner permissions...*, *Deprecated accounts should be removed...* |
| Permanent privileged roles | always-on Owner | *Privileged roles should not have permanent access at the subscription and resource group level* |
| Apps with admin rights | service principal with Owner/Contributor/UAA | *Service Principals should not be assigned with administrative roles...* |

**2. CIEM in Defender CSPM.**

- **Enable:** Defender for Cloud > Environment settings > *subscription* > Defender CSPM plan > **Settings** > **Permissions Management (CIEM)** = On. It is ==!not available on free Foundational CSPM==. Enabling Defender CSPM assigns the **Azure CSPM** standard, which carries the CIEM recommendations; results appear within a few hours.
- **Azure recommendations:** ==@Azure overprovisioned identities should have only the necessary permissions== and ==@Permissions of inactive identities in your Azure subscription should be revoked==. AWS and GCP have equivalents.
- **Logic since 2 February 2026:** inactivity is judged on **unused role assignments** (not sign-ins), with a **90-day** lookback (previously 45). Identities created in the last 90 days are not judged inactive. The **Permissions Creep Index (PCI)** score is deprecated.
- **Context:** Cloud Security Explorer ("who can reach this storage account?"), attack path analysis and the CIEM workbook show which overprivileged identities matter most.
- **Background:** Microsoft Entra Permissions Management (the standalone CIEM product) is deprecated; CIEM is now native in Defender for Cloud.

> **Product docs disagree with each other:** the identity recommendations reference still describes the inactive-identity check as "the past 45 days"; the release notes (February 2026) say 90 days. The newer release note reflects current logic.

**3. Access reviews of Azure resource roles (PIM).**

- Microsoft Entra admin center > **ID Governance > Privileged Identity Management > Azure resources** > *subscription* > **Access reviews > New** (for directory roles choose **Microsoft Entra roles** instead).
- Settings that matter: **Frequency** (one time, weekly, monthly, quarterly, semi-annually, annually); scope (roles such as Owner, Contributor; assignment type active/eligible); **Reviewers** — selected users, **members (self)**, or **manager** with a fallback reviewer.
- **Upon completion:** ==+Auto apply results to resource = Enable== and ==+If reviewers don't respond = Remove access== make removal the default. Other options: No change, Approve access, Take recommendations.
- **Show recommendations** suggests deny for users with no sign-in in the last **30 days**.
- Nothing changes until the review completes; then status moves Completed → Applying → **Applied**, and denied users lose the role within minutes.
- ==!A user who holds the role through a security group is not removed from the group== on denial; an administrator must act.

**4. Right-sizing outcomes.** Remove (dormant, departed, unused SPs). Downgrade (Owner → Contributor or a service role, subscription → resource group). Convert to **PIM eligible** (occasional need; activation expires). Retain with the review approval as audit evidence. Always add the narrower assignment before removing the broader one.

**5. Reach for the right tool.** Defender CSPM = *usage*-based. The MCSB identity recommendations = *configuration*-based (counts and account states). Access reviews = *human attestation* with an audit trail.

> **Contradiction:** the training unit attributes the "too many owners" check to **Azure Advisor** under the name "Azure subscriptions shouldn't contain multiple Owners". Product docs list it as the Defender for Cloud recommendation **"A maximum of 3 owners should be designated for subscriptions"**; Advisor's Security tab surfaces Defender for Cloud recommendations. Use the Defender for Cloud name.

## Where it lives

- **Find:** Azure portal > Microsoft Defender for Cloud > **Recommendations** (filter category *Identity*, or search "overprovisioned" / "inactive"). The same recommendations also show in the Defender portal's Recommendations page.
- **Enable CIEM:** Defender for Cloud > Environment settings > *subscription* > Defender CSPM > Settings.
- **Inspect:** Azure portal > *subscription* > Access control (IAM) > Role assignments (filter Role = Owner; Type = User).
- **Review:** Microsoft Entra admin center > ID Governance > Privileged Identity Management > Azure resources > Access reviews.

```bash
# Every Owner at or below a subscription, including inherited
az role assignment list --scope /subscriptions/<sub> --role Owner --include-inherited --output table

# Replace a broad assignment: add narrow first, then remove broad
az role assignment create --assignee <upn> --role "Virtual Machine Contributor" --scope /subscriptions/<sub>/resourceGroups/rg-app
az role assignment delete --assignee <upn> --role Owner --scope /subscriptions/<sub>
```

## Exam traps

- "Find identities that hold permissions they never use" → **Defender CSPM CIEM** (not Foundational CSPM, not Advisor).
- "Make access removal the default if managers ignore the review" → **If reviewers don't respond: Remove access** + auto apply.
- "Admins need Owner twice a month" → **PIM eligible** assignment, not a standing one.
- "Guest has Owner" → remove; flagged by the guest/external-accounts recommendations.
- "Review denied a user but they still have access" → role came through a **group**; review does not edit group membership.
- "Recommend a maximum number of subscription owners" → **3** (and more than one).
- "Inactive" now means unused role assignments over **90 days**, not "no sign-in".
