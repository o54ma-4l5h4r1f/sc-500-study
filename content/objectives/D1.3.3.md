## Azure first

- **Defender for Cloud** has a free posture tier (**Foundational CSPM**) and paid plans (**Defender CSPM**, Defender for Servers, Storage, SQL and so on). CSPM = cloud security posture management: "is it configured safely?".
- **Environment settings** is Defender for Cloud's per-scope settings page. A scope is a management group, a subscription, an AWS account or a GCP project.
- Defender for Cloud's checks are mostly **Azure Policy** definitions underneath. A recommendation is what you see when a resource fails one.
- **Secure score** is the percentage Defender for Cloud gives your posture; fixing recommendations raises it.

See the Foundations pages listed above, especially *defender-for-cloud-basics*.

## In one sentence

You control *what* Defender for Cloud checks by choosing **security standards** and tuning their **recommendations** (Audit, Disabled, Deny, Enforce, parameters), and you close the gaps with **Fix**, **policy remediation tasks**, **governance rules** and **exemptions**.

## Why it exists

As an analyst you read recommendations. As an engineer you decide which ones exist, which ones block deployments, and who must fix the rest by when. Out of the box you get hundreds of findings. Without tuning, the list is noise. Without owners and deadlines, it never shrinks.

## What actually matters

**1. Standards.** A standard is a set of controls; each control maps to recommendations. ==@MCSB== is assigned by default to every onboarded Azure subscription, AWS account and GCP project. Regulatory standards are added on top (needs a paid plan other than Servers Plan 1 / APIs Plan 1 — see D1.3.2). One misconfiguration can appear under several standards, but it is one recommendation.

> **Contradiction:** the training unit says MCSB "can't be removed". Product docs show the MCSB standard can be turned on and off on the Security policies page, and recommend disabling Azure standards you no longer need. Defender for Cloud **exemptions require MCSB to be assigned**, so in practice keep it on. Product docs win.

**2. Tune recommendations in MCSB** (Environment settings > scope > Security policies > MCSB > ... > *Manage recommendations* > *Manage effect and parameters*):

| Setting | Effect |
|---|---|
| **Audit** | recommendation on (default) |
| **Disabled** | recommendation and all its sub-recommendations off for that scope |
| **Deny** | new non-compliant resources are blocked (Azure only, subset of recommendations) |
| **Enforce** | uses `deployIfNotExists` to fix resources automatically at creation; set it from the **recommendation details page** |
| **Additional parameters** | Default / Configured / None — e.g. change a diagnostic-log retention value |

**Effect conflict** and **Additional parameters conflict** filters find standards that set different values for the same recommendation. Enforce takes effect immediately, but the recommendation refreshes within up to 12 hours.

**3. Custom standards and custom recommendations.**

- **Custom recommendation (KQL):** Environment settings > subscription > Security policies > **+ Create custom recommendation**. You write a KQL query over `RawEntityMetadata` that returns every resource with `HealthStatus` = `UNHEALTHY` or `HEALTHY`. Works for Azure, AWS and GCP. ==!Needs the paid Defender CSPM plan.== Creator needs **Security Admin**.
- **Custom standard:** Security policies > **+ Create > Standard**, then pick built-in and custom recommendations. Creator needs **Owner** on the subscription.
- **Legacy route:** a custom Azure Policy initiative with `"ASC": "true"` in its metadata onboards as a custom standard. Available to all customers; Microsoft now recommends the KQL route.

> **Contradiction:** one training unit says custom standards require Defender CSPM; another says any Azure Policy initiative becomes a standard. Product docs: **KQL-based custom recommendations need Defender CSPM; Azure Policy-based custom recommendations are available to everyone.**

**4. Four ways to close a finding.**

| Situation | Use |
|---|---|
| Recommendation shows **Fix**, change is safe | **Fix**: select resources > Fix > review the logic > confirm |
| Backed by a `deployIfNotExists`/`modify` policy (agents, diagnostic settings) | **Policy remediation task** (D1.3.1) |
| Owner must decide or change app code | **Governance rule** |
| Compensating control or accepted risk | **Exemption** |

**Governance rules** (Environment settings > scope > *Governance rules*): conditions by severity or specific recommendation; owner **by resource tag** or by email; remediation timeframe **7, 14, 30 or 90 days**; optional **grace period** (MCSB recommendations do not hit secure score until overdue); **priority** decides which rule wins; owners get a **weekly email**, and their manager gets overdue items. Conflicting rules apply in scope order — management-group-level rules before subscription-level ones. The **Governance report** shows on time / overdue / unassigned by owner.

**Exemptions** (recommendation > Exempt, or Environment settings > *Exemptions* for at scale): scope (management group, subscription, or selected resources), name, optional expiry, category:

- ==@Mitigated== ("resolved through third-party service"): the resource counts as **healthy**; secure score goes **up**.
- ==@Waiver== ("risk accepted"): the resource is **excluded** from the calculation; score impact is **neutral**.

> **Contradiction:** the training unit says a waiver "removes the resource from the denominator, improving the score". Product docs say a waiver is **neutral** and **mitigated** is the one that raises the score. Product docs win.

Exemptions need **Owner or Security Admin** (plus `Microsoft.Authorization/policyExemptions/write` and `.../policyAssignments/exempt/action` on every initiative containing the recommendation), take up to **24 hours**, and are capped at 5,000 resources per subscription.

**5. The Defender portal is taking over posture policy (preview).** In the Defender portal, *Exposure Management > Policies* holds the Microsoft-managed **MDC Baseline Policy** (assigned to all connected environments, can be disabled, never deleted) and your **custom posture policies**. Limits today: Azure environments only, **Audit only** — ==!Deny stays in Azure Policy==, and custom KQL recommendations stay in the Azure portal. Delegation uses Defender unified RBAC permission **Core security settings (Manage / Read)**. Environments managed in Defender need **Defender CSPM**; there is no free Foundational CSPM there.

**6. Roles.** ==@Security Reader== views recommendations and policy. ==@Security Admin== also updates security policies and dismisses alerts. Owner is needed to create a custom standard.

## Where it lives

- Azure portal > Microsoft Defender for Cloud > **Environment settings** > *scope* > **Security policies** (Standards tab, + Create) | **Governance rules** | **Exemptions** | Defender plans | Settings & monitoring.
- Azure portal > Microsoft Defender for Cloud > **Recommendations** > *recommendation* > **Take action** (Remediate / Fix, Assign owner & due date, Exempt, Workflow automation) and **Enforce** / **Deny**.
- Defender portal (`security.microsoft.com`) > **Exposure Management > Policies** (preview posture policies).

## Exam traps

- "Prevent new non-compliant resources from the recommendation" → **Deny**. "Auto-fix at creation" → **Enforce**. "Turn a noisy check off for a dev subscription" → **Disabled** at that scope (or an exemption if it is one resource).
- "Org-specific check across AWS and Azure" → KQL **custom recommendation** + Defender CSPM.
- "Each team must fix its own findings within 30 days" → **governance rule**, owner by tag.
- "Third-party tool already handles it" → exemption **Mitigated**. "Leadership accepts the risk" → **Waiver**.
- "Fix appears but breaks an old HTTP client" → Fix applies exactly the shown change; review it first.
- Deny/Enforce exist for **Azure** resources only, and only on some recommendations.
- Exemption silently fails → missing permission on one of the initiatives, or MCSB not assigned.
