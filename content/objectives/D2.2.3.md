## Azure first

- **Microsoft Defender for Cloud** sells protection as **plans** you switch on per subscription in **Environment settings**. The **Databases** plan is a bundle of four separately priced subplans.
- Azure has several database families: **Azure SQL** (SQL Database, SQL Managed Instance, Synapse dedicated SQL pools), **SQL Server you run yourself** on a VM or an on-premises server, **open-source** managed databases (Azure Database for PostgreSQL / MySQL flexible server), and **Azure Cosmos DB** (NoSQL).
- **Azure Arc** projects a non-Azure machine into Azure so Azure services can manage it (see azure-arc-and-hybrid-machines).

Read first: defender-for-cloud-basics, azure-sql-basics, azure-arc-and-hybrid-machines, azure-policy-basics.

## In one sentence

Defender for Databases is four Defender for Cloud subplans (Azure SQL, SQL servers on machines, open-source relational, Cosmos DB) that alert on SQL injection, brute force and anomalous access, and, for the SQL plans, run vulnerability assessment scans; you enable them per subscription and route the alerts to email and Sentinel.

## Why it exists

Auditing (D2.2.2) records everything but tells nobody. A SQL injection or a brute-force run sits in the logs until someone queries them. As an analyst you triaged "Potential SQL injection" and "Login from a suspicious IP" alerts; this plan produces them, and vulnerability assessment tells the database owner which misconfigurations made the attack possible.

## Mental model

An **alarm company for four kinds of building**. One contract, four separately priced packages: the company's own office towers (Azure SQL PaaS), houses you built yourself anywhere (SQL Server on VMs and Arc machines, which need a small device fitted: the Defender for SQL extension), rented flats (PostgreSQL/MySQL flexible server, Amazon RDS) and the warehouse (Cosmos DB). The SQL packages also include a yearly inspection report (vulnerability assessment).

## What actually matters

| Subplan | Protects | Vulnerability assessment | Notes |
|---|---|---|---|
| ==@Defender for Azure SQL Databases== | SQL Database (single + elastic pools), SQL Managed Instance, Synapse dedicated SQL pools (read/write replicas) | ==+Yes== (express config is auto-enabled) | agentless |
| ==@Defender for SQL Servers on Machines== | SQL Server 2012+ on Azure VMs and on Arc-enabled SQL Server instances (on-premises, AWS, GCP) | Yes | needs the **Defender for SQL extension** (and SQL IaaS extension); deploying needs **Subscription Owner** |
| ==@Defender for Open-Source Relational Databases== | Azure Database for PostgreSQL and MySQL **flexible server** (all tiers); Amazon RDS Aurora PostgreSQL/MySQL, PostgreSQL, MySQL, MariaDB | ==!No== | ==!not on VMs or Arc machines== |
| ==@Defender for Azure Cosmos DB== | Cosmos DB accounts, **NoSQL API only** | No | does not read account data |

1. **Enable**: `Defender for Cloud > Environment settings > {subscription} > Defender plans > Databases = On` turns on all four; **Select types** lets you pick subplans. Subscription enablement covers new resources automatically. Azure SQL and open-source plans can also be enabled per resource.
2. **At scale**: built-in policy *Configure Azure Defender for Azure SQL database to be enabled* (DeployIfNotExists), *Configure Azure Defender for open-source relational databases to be enabled*, or the initiative *Configure Microsoft Defender for Databases to be enabled* (4 policies, all subplans), assigned at management-group scope. Audit-only cousins: *Azure Defender for SQL should be enabled for unprotected Azure SQL servers* / *...unprotected SQL Managed Instances* (AuditIfNotExists).
3. **Detections** (all plans): potential SQL injection, anomalous access and query patterns (unusual location, brute force), suspicious activity (host talking to crypto-mining C2). Alerts carry a MITRE ATT&CK tactic and can continue into Microsoft Sentinel. Cosmos DB adds key-listing patterns and Tor access.
4. **Vulnerability assessment (VA)** scans for misconfigurations, excessive permissions and unprotected sensitive data, with remediation scripts. Set a **baseline** to accept a finding as intended; later scans flag only drift.

| | ==+Express configuration== (recommended) | Classic configuration |
|---|---|---|
| Scan results stored | by Defender for Cloud, same region as the server | ==!your storage account== |
| Recurring scan | always on | configurable |
| Apply baseline | immediately | after a rescan |
| Supported (product docs) | SQL Database, SQL MI (needs a system-assigned managed identity on the MI), Synapse | SQL Database, SQL MI, Synapse |
| Change settings role | **SQL Security Manager** | SQL Security Manager + Storage Blob Data roles on the storage account |

   View results in Defender for Cloud recommendations: **Security Reader** or **Security Admin**. Classic VA APIs retire **August 16, 2027**.

5. **Alert routing**: email notifications per subscription (send High to a SOC distribution list), Microsoft Sentinel via the Defender for Cloud data connector, **suppression rules** scoped tightly to resource + alert type with an expiry, and **sample alerts** to test the pipeline.

> **Two contradictions to know.** (a) The training module (unit 2) and the *Defender for Azure SQL Databases* overview list SQL Server on Azure VMs and Arc under the Azure SQL plan; the Databases plan overview, quickstart and the enablement page put them in the separate **Defender for SQL Servers on Machines** subplan, which is what the portal shows. (b) Unit 5 says express configuration covers only SQL Database and Synapse; current product docs say express is **GA for SQL Managed Instance** too. Product docs win.

## Where it lives

| Task | Path (Azure portal) |
|---|---|
| Plan and subplans | `Microsoft Defender for Cloud > Environment settings > {subscription} > Defender plans > Databases > Select types` |
| One SQL server / MI | `SQL server > Security > Microsoft Defender for Cloud` (enable, VA settings, findings) |
| VA findings at scale | `Defender for Cloud > Recommendations` (SQL vulnerability findings) |
| Coverage gaps | `Defender for Cloud > Inventory`, recommendation *Azure Defender for SQL should be enabled for unprotected Azure SQL servers* |
| Email, suppression, sample alerts | `Defender for Cloud > Environment settings > Email notifications`; `Security alerts > Suppression rules / Sample alerts` |

## Exam traps

- "Protect SQL Server on an on-premises server": ==+Arc-enable it + Defender for SQL Servers on Machines==. Not Defender for Azure SQL Databases.
- "Protect PostgreSQL running on a VM": ==!not covered== by the open-source plan.
- "Need vulnerability assessment for MySQL": the open-source plan has ==!no VA==.
- "VA without managing a storage account": ==+express configuration==.
- "Cosmos DB MongoDB API alerts": ==!unsupported==; NoSQL API only.
- Turning on the Azure SQL toggle does not turn on the open-source toggle (subplans are independent), but turning on the **Databases** plan enables all four.
- A suppression rule scoped only by alert type hides attacks on every database. Scope it to the resource.
