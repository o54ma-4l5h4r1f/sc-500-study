## Azure first

- **Microsoft Defender for Cloud** is Azure's security service. Its free part scores your setup (posture). Its paid **plans** protect one kind of workload each: servers, storage, SQL, containers.
- **Defender for Servers** is the paid plan for machines. It comes in **Plan 1** and **Plan 2**. You switch it on in **Environment settings** for an *Azure subscription*, an *AWS account* or a *GCP project*.
- An **Azure VM** is already an Azure resource, so Defender for Cloud sees it the moment the plan is on.
- A server **outside Azure** (in your data centre, in AWS, in GCP) is invisible to Azure until something connects it. The normal "something" is **Azure Arc**: a small agent that turns the server into an Azure resource.
- **Microsoft Defender for Endpoint (MDE)** is the EDR sensor you know from analyst work. Defender for Servers installs it for you.

See the Foundations pages listed above: Defender for Cloud basics, VMs and disks, Azure Arc, and AWS/GCP for Azure people.

## In one sentence

Onboarding to Defender for Servers means turning the Servers plan on (Plan 1 or Plan 2) at a subscription, AWS account or GCP project — and making sure every non-Azure machine is first connected through **Azure Arc** so the plan can see and protect it.

## Why it exists

As an analyst you triaged alerts that said "Detection source: Microsoft Defender for Servers". Someone had to switch that on. That someone is now you.

Think of a building's alarm contract. It covers named floors; a floor not on the contract raises no alarms. Defender for Servers is the contract. The subscription (or AWS account, or GCP project) is the list of floors. Arc is the cable that wires an off-site annex into the same panel.

The rule behind the picture: ==@Defender for Servers protects Azure resources==. Make the machine an Azure resource (natively, or through Arc) and put it in a subscription where the plan is on.

## What actually matters

1. **Plan 1 vs Plan 2.** Plan 1 is the EDR plan: MDE integration plus agent-based vulnerability scanning. Plan 2 is Plan 1 plus agentless scanning, JIT VM access, File Integrity Monitoring, OS baseline and OS update assessment, premium Defender Vulnerability Management (MDVM), network map, Azure network-layer and DNS threat detection, and the **500 MB/day free ingestion** benefit. When you toggle Servers to **On**, the portal selects ==@Plan 2 by default==. The full feature table sits below.

2. **Scope: subscription first, resource level second.** Microsoft recommends enabling at the subscription. You can then fine-tune per machine. ==!Plan 2 cannot be enabled on a single resource==. Only Plan 1 can be switched on per machine; both plans can be switched *off* per machine. Per-machine changes go through the REST API (`Microsoft.Security/pricings` on the VM), a PowerShell script, or Azure Policy keyed on a tag. There is no per-VM toggle in the portal.

3. **On-premises servers: Arc first.** Install the Azure Connected Machine agent (Arc) and the server becomes an Arc-enabled server. In a subscription with the plan on, it is protected automatically and gets the MDE extension. The alternative, **Direct onboarding**, uses servers already in MDE. It needs no Arc, but gives only Plan 1 plus a ==!subset== of Plan 2 (the Arc-dependent Plan 2 features still need Arc). It also gives no Azure Policy or Machine Configuration (Guest Configuration). It applies to **all** eligible non-Azure servers in the tenant; you cannot pick a pilot group. It needs **Owner** on the target subscription and **Security Administrator** in Entra ID.

4. **AWS and GCP: the connector does Arc for you.** Connect the AWS account or GCP project to Defender for Cloud (the connector itself is D4.1.4). Then turn on the Servers plan at the connector. By default the connector **auto-provisions Arc** onto each EC2 instance or GCP VM. That needs **Owner** on the Azure subscription. It also needs the **AWS SSM Agent** (EC2) or the **OS Config agent** (GCP) on each machine. No SSM Agent, no Arc, no full protection.

5. **What happens the moment you click Save.** A **30-day trial** starts. You ==!can't stop, pause or extend== it. The MDE extension (**MDE.Windows** / **MDE.Linux**) is auto-installed on supported machines. MDVM vulnerability assessment turns on. With Plan 2, agentless scanning turns on by default. FIM is ==!not== on by default; you configure it afterwards.

6. **The 500 MB benefit needs a workspace step.** Plan 2's free 500 MB per machine per day applies at the **Log Analytics workspace**. You must also turn on Defender for Servers Plan 2 **on that workspace**. The allowance is pooled across all machines in the subscription, not enforced per machine. It covers specific security tables only (for example `SecurityEvent`, `SecurityAlert`, `MDCFileIntegrityMonitoringEvents`). Plan 1 needs no workspace at all.

| Premium MDVM features | No | Yes | Defender portal only |

### Deployment scope

| Scope | Plan 1 | Plan 2 |
|---|---|---|
| Enable for a subscription / AWS account / GCP project | Yes | Yes |
| Enable for one resource (VM, scale set, Arc machine) | ==+Yes== | ==!No== |
| Disable for one resource | Yes | Yes |

> **Contradiction — product docs win.** The training unit says you can "override the subscription-level plan setting at the resource group or individual resource level" and apply Plan 1 to dev resource groups. The product docs and the API say the override is **per resource** (there is no resource-group pricing scope; a script or Policy assignment can *target* the machines in a resource group, but the setting lands on each machine), and ==!only Plan 1 can be enabled== at that level. For the exam: per-resource, Plan 1 only, disable allowed for both. Also note the scale article: at **subscription** level you pick ==@one== plan (P1 or P2), never both; to run both plans as subscription defaults, split subscriptions across two management groups with one Policy assignment each.

## Where it lives

**Azure portal > Microsoft Defender for Cloud > Management > Environment settings > *subscription / AWS account / GCP project* > Defender plans > Servers > On.** Then use **Change plans** to pick Plan 1 or Plan 2, and **Save**.

![Turning the Servers plan on in Environment settings](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/tutorial-enable-servers-plan/enable-servers-plan.png){Defender plans page: toggle Servers to On. It defaults to Plan 2.}

![Change plans link on the Servers row](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/tutorial-enable-servers-plan/servers-change-plan.png){Change plans switches between Plan 1 and Plan 2}

![Plan 1 or Plan 2 selection pop-up](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/tutorial-enable-servers-plan/servers-plan-selection.png){Pick the plan, Confirm, then Save}

- **Free 500 MB benefit:** same blade, select the **Log Analytics workspace** instead of the subscription, turn on Defender for Servers Plan 2. To turn Plan 2 off later you must also turn it off on each workspace.
- **Direct onboarding:** **Environment settings > Direct onboarding > On**, then pick the subscription. Servers can take up to 24 hours to appear.
- **Check coverage:** **Defender for Cloud > Inventory**, filter by resource type (Azure VM vs Arc-enabled server), or the **Coverage workbook**.

![Enabling Defender for Servers Plan 2 on a Log Analytics workspace](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/tutorial-enable-servers-plan/enable-workspace-servers.png){Plan 2 on the workspace is what turns on the 500 MB/day free ingestion}

![Direct onboarding toggle in Environment settings](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/onboard-machines-with-defender-for-endpoint/direct-onboarding-subscription.png){Direct onboarding: tenant-wide, no Arc, limited Plan 2 features}

Code (subscription scope, then one VM on Plan 1):

```bash
# Subscription: Defender for Servers Plan 2
az security pricing create --name VirtualMachines --tier Standard --subplan P2
```

```bicep
// Subscription-scope deployment
resource servers 'Microsoft.Security/pricings@2024-01-01' = {
  name: 'VirtualMachines'
  properties: {
    pricingTier: 'Standard'
    subPlan: 'P2'
  }
}
```

```json
// PUT .../providers/Microsoft.Compute/virtualMachines/{vm}/providers/Microsoft.Security/pricings/virtualMachines?api-version=2024-01-01
{ "properties": { "pricingTier": "Standard", "subPlan": "P1" } }
// pricingTier "Free" disables the plan on that one VM; DELETE removes the override
```

At scale use Azure Policy, category **Security Center – Granular Pricing**: *Configure Azure Defender for Servers to be enabled (with 'P1' subplan) for all resources with the selected tag*, and its sibling *…to be disabled for resources (resource level) with the selected tag*. Both are DeployIfNotExists; create a remediation task for existing machines.

## Exam traps

- ==!"Enable Plan 2 on just these three VMs."== Not possible. Plan 2 is subscription (or connector) scope. Per-resource enable is Plan 1 only.
- ==!"Install MDE manually on every Azure VM first."== Wrong. The plan auto-deploys MDE.Windows / MDE.Linux. Manual work is only for opt-out cases.
- **On-premises server, full Plan 2 features (FIM, OS updates, Policy)?** ==+Onboard with Azure Arc==. ==!Direct onboarding== gives Plan 1 plus only a subset of Plan 2, and no Azure Policy or Machine Configuration.
- **AWS EC2 not showing as protected?** Check the **SSM Agent** and the Arc auto-provisioning. Also check you are **Owner** on the subscription. GCP needs the **OS Config agent**.
- **Trial:** 30 days. It cannot be paused or extended. Plan the evaluation before you click.
- **500 MB/day:** ==!Plan 2 only==, pooled per subscription, and it needs Plan 2 enabled **on the workspace**. A DCR on its own does not trigger it.
- **Plan 1 needs a Log Analytics workspace?** No. Plan 2 needs one only for FIM and the ingestion benefit.
- **The Log Analytics agent (MMA) is not part of onboarding.** It retired in August 2024. Defender for Servers now relies on MDE plus agentless scanning; AMA is only for the 500 MB benefit data.
- **Turning the plan off** at the subscription does not turn it off on a workspace where you enabled Plan 2. That is a separate switch.
