## Azure first

- A Sentinel **workspace** is a Log Analytics workspace inside a **resource group**. Anything you install from the content hub is deployed as Azure resources into that workspace and resource group.
- Installing a solution is an **ARM template deployment** (Azure Resource Manager — Azure's "build these resources from a recipe" engine). That's why the wizard asks for subscription, resource group and workspace, and why you can download the template.
- **Azure Marketplace** is Microsoft's catalogue for first-party and partner offerings. Content hub solutions are published through it.

See the Foundations pages listed above: Log Analytics workspace, Defender portal tour, Azure RBAC vs Entra roles, and infrastructure as code basics.

## In one sentence

The content hub is Sentinel's built-in catalogue where you install and update **solutions** — packages of data connectors, analytics rule templates, workbooks, hunting queries, parsers, playbook templates and watchlists — into a workspace.

## What's new for an engineer

As an analyst you used rules and workbooks that "came with" Sentinel. Somebody installed them. Now that's you:

1. **Role.** Install, update or delete solutions and standalone content: ==@Microsoft Sentinel Contributor== at the **resource group** level. Responder and Reader can't.
2. **Connectors come from solutions.** Since the content hub took over, most data connectors (including Azure Activity, Microsoft Entra ID, Microsoft 365) appear on the Data connectors page only **after** you install their solution.
3. **Install ≠ enable.** Installing drops *templates* into the workspace. You still connect the connector, create rules from templates, save workbooks and create playbooks.
4. **Updates are your job.** Solutions show **Update** in the status column and count toward the **Updates** total at the top of the page. You update them; standalone content updates itself.

## What actually matters

- **Solution vs standalone content.** A solution is a package with lifecycle management (versions, Update). Standalone content is a single item that is kept up to date automatically. To use one item inside a solution you must install the whole solution.
- **Support models.** Each item is **Microsoft-supported**, **Partner-supported** (contact the partner) or **Community-supported** (raise a GitHub issue). Shown in the details pane's Support box.
- **Install with dependencies.** Domain solutions that rely on the unified AMA connectors (CEF, Syslog, custom logs) offer **Install with dependencies** so the connector solution comes along.
- **Bulk operations.** Switch to list view, tick several items, select **Install/Update**. Already-current items are skipped.
- **Active content is never overwritten.** Updating a solution refreshes *templates* only. Rules you already created stay as they are; a scheduled rule whose template changed shows an **Update** badge, and you choose **Review and update** (compare YAML side by side) or leave it.
- **Manage.** For solutions at version 2.0.0 or higher, **Manage** lists every content item and its status, with buttons to open the connector page, create a rule, save a workbook or create a playbook.
- **As code.** The wizard's **Download a template for automation** link gives the ARM template; the **Get Product Package** / **Get Product Template** APIs return a `properties.mainTemplate` you deploy with ARM.

## Where it lives

| Task | Portal and path |
|---|---|
| Find / install / update | Defender portal > **Microsoft Sentinel > Content management > Content hub** (Azure portal: Sentinel > Content management > Content hub) |
| Single install | Select solution > **View details** > **Create** / **Update** > Basics (subscription, resource group, workspace) > tabs > Review + create |

| Enable items | Installed solution > **Manage** > pick content item |
| Template drift on rules | Analytics > Active rules > rule with **Update** badge > **Review and update** |

## Exam traps

- ==!"Microsoft Sentinel Responder can install a solution"== — no. ==+Microsoft Sentinel Contributor== at the resource group.
- ==!"Updating a solution updates my active analytics rules"== — no. Only templates change; active rules show an Update badge and you decide.
- ==!"The connector is missing, so it isn't supported"== — usually the solution isn't installed yet.
- **"Installed the solution, no data"** → you still have to open the connector page and connect it.
- **Partner-supported** problem → contact the partner, not Microsoft support.
- **Deploy content consistently to many workspaces** → download the ARM template or use repositories (CI/CD); don't click through each workspace.

## Skip

- **Skip** unit 3 of the module, *Use repositories for deployment* (connect GitHub or Azure DevOps, deployment scripts, customizing deployments). The map flags it off-blueprint: the bullet is content hub solutions. Know only that repositories manage *custom* content as code.
- **Skip** the per-content-type click paths on the Manage page (clone a hunting query, save a workbook copy, load parser code). They are analyst-side steps; the screenshots below are enough.
- **Skip** the solution authoring guide (packaging and publishing your own solution to Marketplace). Partner work, not configuration.
- **Skip** the content category list (Security – Network, Compliance, IT Operations…). Filter labels.
- **Skip** template major/minor version semantics. Know that rules remember their template and can be updated or reverted.
