## Azure first

- A VM's **managed disk** holds its operating system and files. A **snapshot** is a point-in-time, read-only copy of that disk, made without stopping the VM.
- Disks are always encrypted at rest. With **platform-managed keys (PMK)** Azure holds the key. With **customer-managed keys (CMK)** your key sits in **Key Vault**, and anyone who wants to read the disk needs permission to use that key.
- **Defender CSPM** is the paid posture plan in Defender for Cloud. **Defender for Servers Plan 2** is the top server plan. Both include agentless scanning.
- In AWS the equivalent of a VM is an **EC2 instance**; in GCP it is a **Compute Engine instance**. They reach Defender for Cloud through a connector.

See Defender for Cloud basics, VMs and disks, keys/secrets/certificates and AWS/GCP for Azure people in Foundations.

## In one sentence

Agentless scanning is Defender for Cloud taking a snapshot of each running VM's disks once a day, reading it in an isolated Microsoft environment, and reporting software inventory, vulnerabilities, plaintext secrets and (Plan 2 only) malware — with nothing installed on the VM.

## Why it exists

Agents fail: change control blocks them, they crash, or an attacker kills them. As an analyst you saw intruders stop the sensor first.

Agentless scanning is an inspector who photocopies the blueprints at night and studies them at the office. Nobody inside can stop it. It is not CCTV: it sees the building as it was at copy time, once a day.

## What actually matters

1. **Which plan.** ==@Defender for Servers Plan 2== or ==@Defender CSPM== gives software inventory, vulnerability assessment and secrets scanning. **Malware scanning is Plan 2 only.** Its alerts land in Defender for Cloud and Defender XDR. Plan 1 has no agentless scanning at all. It covers Azure VMs, AWS EC2 and GCP Compute Engine instances. It is **on by default** when you enable either plan.

2. **One switch, all capabilities.** There is one **Agentless scanning for machines** setting per environment (subscription, AWS account, GCP project). You ==!can't turn individual capabilities on or off==. The plan decides what you get.

3. **Schedule and state.** It runs **once every 24 hours** on a ==!non-configurable== schedule. Only machines that are **running** at scan time are scanned. Stopped or deallocated VMs are skipped until a later cycle. Allow 24 hours after enabling before troubleshooting.

4. **Coverage limits (Azure).** Standard VMs and flexible-orchestration scale sets are supported. Combined disk size up to **4 TB**: all disks are scanned. Over 4 TB: only the OS disk (if it is under 4 TB). A VM with more than **14 disks** is not supported. A VM is skipped entirely if any disk is `UltraSSD_LRS`, `PremiumV2_LRS` or an AKS ephemeral OS disk. So are Databricks VMs and ReFS/ZFS/UFS file systems.

5. **Encryption.** PMK disks work out of the box. **CMK disks** need you to grant Key Vault access to the **Microsoft Defender for Cloud Servers Scanner Resource Provider** (app ID `0c7668b5-3260-4ad0-9f53-34ed54fa19b2`). With an RBAC vault, give it ==@Key Vault Crypto Service Encryption User==. With an access-policy vault, give it **Get, Wrap Key, Unwrap Key**. Until you do, CMK VMs are silently not scanned. In Azure the built-in role **VM scanner operator** (read-only disk permissions) is added to the subscription automatically when you enable scanning.

6. **Exclusions by tag.** To skip machines, use **Agentless scanning for machines > Edit configuration** and enter `tag:value` pairs. You can enter more than one pair. Matching machines are skipped.

### Agentless vs agent-based

| | Agentless (snapshot) | Agent-based (MDE sensor) |
|---|---|---|
| Plan | P2 or Defender CSPM | P1 or P2 |
| Install on VM | ==+nothing== | MDE.Windows / MDE.Linux |
| Freshness | every 24 h, fixed | ==+continuous== |
| Machine must be | running at scan time | running and connected |
| Survives sensor tampering | ==+yes== | no |
| Real-time EDR / response | ==!no== | yes |
| Malware | P2: scheduled point-in-time scan | real-time AV |

When both report a VM, ==@agent-based results== are shown. Agentless is the safety net.

> **Contradiction — product docs win.** The training unit says the maximum is **six** disks per VM. The current product article says VMs with **more than 14 disks** aren't supported. Use **14** for the exam.

## Where it lives

**Azure portal > Microsoft Defender for Cloud > Environment settings > *subscription / AWS account / GCP project* > Defender CSPM or Defender for Servers Plan 2 > Settings > Settings and monitoring > Agentless scanning for machines > On > Save.** Then use **Edit configuration** on the same row for exclusion tags.

- **AWS:** same toggle on the AWS connector, then **download and deploy the CloudFormation template** (the stack grants the `VmScanner` role). For a management account, deploy it as both a stack and a StackSet.
- **GCP:** same toggle on the GCP connector, then **run the onboarding script**. A GCP organisation policy can block snapshot creation.
- **Findings:** recommendations such as *Machines should have secrets findings resolved*; CVEs in the vulnerability recommendations; malware as security alerts.

## Exam traps

- ==!"Agentless scanning is in Plan 1."== No. P2 or Defender CSPM.
- ==!"Defender CSPM gives agentless malware scanning."== No. Malware is Plan 2 only.
- ==!"Schedule it to run at 02:00."== The 24-hour schedule cannot be changed.
- **Deallocated VMs** are not scanned.
- **CMK-encrypted disks not scanned?** Grant the scanner resource provider **Key Vault Crypto Service Encryption User** (RBAC) or Get/Wrap/Unwrap (access policy).
- **VM with an Ultra Disk or Premium SSD v2 attached** is skipped entirely, not just that disk.
- **Exclude a VM from agentless scanning only** = tag exclusion in **Edit configuration**. Excluding the VM from the **whole plan** (resource-level disable, D3.2.5) is a different, bigger hammer.
- **It's not real-time protection.** If the question needs blocking or response, the answer is the MDE agent (D3.2.6).

## Skip

- **Skip:** the AWS IAM permission tables (`VmScannerDeleteSnapshotAccess`, KMS grants) and the 250-snapshot suspension safeguard. Know only "the CloudFormation template grants the permissions".
- **Skip:** malware-scan partial-coverage thresholds (1 GB archives, 10,000 files, five nesting levels, about 300,000 / 500,000 file targets). These are planning guidance, not testable limits.
- **Skip:** the rollout checklist and troubleshooting tables.
- **Skip:** the GCP custom role names and organisation-policy fix. That is connector plumbing (D4.1.4).
- **Skip:** Kubernetes-node VM scanning. That belongs to the containers objectives.
