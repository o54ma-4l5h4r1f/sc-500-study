## Azure first

- **Security Copilot** is a SaaS service you sign in to at `securitycopilot.microsoft.com`. It also appears *embedded* inside the Defender, Entra, Intune and Purview portals.
- It runs on **Security Compute Units (SCUs)** — paid compute. Outside the Microsoft 365 E5/E7 inclusion, SCUs are an **Azure resource** ("Microsoft Security compute capacities") that lives in a **subscription** and **resource group** you pick. That is the Azure piece: someone needs Azure Owner or Contributor there.
- A **workspace** is a container *inside your Entra tenant* that ties together one capacity, one data storage location, its own settings and its own owners and contributors.
- **Microsoft Purview Audit** is the tenant audit log. Security Copilot can write its admin and user actions there.

See the Foundations pages listed above: resource hierarchy, tenants and licensing, the security stack map and Purview basics.

## In one sentence

A Security Copilot workspace is a tenant-scoped box with its own SCU capacity, its own fixed data storage location, its own settings and its own role list — and you build several of them to split cost, data residency and access between teams.

## What's new for an engineer

As an analyst you typed prompts into a workspace someone else made. Now you make it. That means four decisions an analyst never saw:

1. **Which capacity pays.** Provisioned SCUs (billed every clock hour) plus optional overage SCUs (billed only when used).
2. **Where data rests.** Chosen at creation. ==!It cannot be changed later.== To move geography you create a new workspace.
3. **Where prompts are evaluated.** Same geo, or "evaluate anywhere with available capacity" (faster, but prompts may be processed outside your data geo).
4. **Which workspace each product's embedded experience uses.** A tenant-wide routing setting.

## What actually matters

- **Two capacity models.**
  - *Pay-as-you-go (provisioned + overage).* Minimum ==@1 provisioned SCU==, maximum 100 at onboarding. Microsoft suggests 3 SCUs plus unlimited overage to explore. Overage can be 0–999 or unlimited. Provisioned SCUs are billed in clock-hour blocks with a one-hour minimum. Overage is billed to one decimal place. Unused provisioned SCUs expire at the end of the hour.
  - *Microsoft 365 E5/E7 inclusion.* Microsoft auto-creates a **Default Security Copilot Capacity** and a default workspace. You get 400 SCUs per month per 1,000 paid user licences (up to 10,000 a month). Unused SCUs do not roll over. That capacity cannot be modified, is not billed hourly, and is shared tenant-wide across users and experiences. Usage beyond the allocation will be throttled (a pay-as-you-go option is promised later).
- **SCUs are not shared between workspaces.** If workspace A runs dry, it cannot borrow from workspace B. A capacity resource can be attached to **only one workspace at a time**.
- **When both provisioned and overage run out**, new requests are throttled until the next billing hour.
- **Who can create.** Security Administrator (or a supported Entra/Purview admin role) in the tenant, *plus* Azure Owner or Contributor on the subscription or resource group to create capacity. ==!Global Administrator does not automatically hold Azure Owner== — Entra roles do not grant Azure resource access.
- **Changing SCUs** needs Azure capacity Owner or Contributor; in the Security Copilot portal you must also be a Copilot owner. Changes take effect **within 30 minutes**. The usage dashboard keeps **90 days** of data.
- **Owner settings are per workspace** (capacity, data sharing, file upload) — with one exception: **audit logging to Purview is tenant-wide** and only a Security Administrator can change it.
- **Agent routing.** Under *Workspaces for Microsoft Security Copilot agents* you point Defender, Purview, Intune and Entra each at one workspace. With no assignment, embedded traffic goes to the **default workspace — the oldest one in the tenant**. A user without a role in the target workspace gets an error.
- **Deleting capacity** is permanent: session history and feedback are lost, and it needs Security Administrator. To pause a workspace without losing data, *disassociate* the capacity and remove user access instead. Billing starts the moment capacity is created, attached or not.

## Where it lives

| Task | Where |
|---|---|
| Create a workspace | Security Copilot portal > workspace name in breadcrumb > **New workspace**, or **Owner settings > Manage workspaces > New workspace** |
| Create capacity in Azure | Azure portal > search *Security compute* > **Microsoft Security compute capacities** > Create (then finish in the Security Copilot portal) |
| Change provisioned / overage SCUs | Security Copilot > **Owner settings > Security compute units > Change**, or Usage dashboard > **Change units**; or the capacity resource in the Azure portal |
| Usage dashboard | Security Copilot > home menu > **Owner > Usage monitoring** |
| Route embedded agents | Security Copilot > **Owner settings > Workspaces for Microsoft Security Copilot agents** |
| Purview audit logging | Security Copilot > **Owner settings > Logging audit data in Microsoft Purview** (tenant-wide) |

## Exam traps

- ==!"Move the workspace to the EU later"== — impossible. Data storage location is fixed at creation. ==+Create a new workspace.==
- ==!"Share spare SCUs from the SOC workspace with the compliance workspace"== — not supported. Each workspace has its own capacity.
- "Overage" is *on-demand extra*, not a monthly commitment. Provisioned is the hourly baseline.
- Embedded experiences do **not** let the user pick a workspace; the tenant-wide routing setting decides.
- Workspace names cannot be renamed (contact Support). Capacity association *can* be changed, but a workspace without capacity does not work.
- E5 inclusion capacity: the cost numbers shown in the UI are informational only.
