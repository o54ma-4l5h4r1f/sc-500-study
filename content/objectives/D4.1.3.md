## Azure first

- A **Defender plan** is a paid switch for one workload type — servers, storage, databases and so on. Internally it is a `Microsoft.Security/pricings` setting with tier **Free** or **Standard** (plus an optional sub-plan such as `P1`/`P2`).
- You set plans in **Environment settings**, Defender for Cloud's settings page for each scope: management group, subscription, AWS account, GCP project — and, for two plans, a **Log Analytics workspace**.
- Some plans deploy an **extension** (a small agent or setting) to the protected resource; most read Azure platform data and install nothing.
- **Azure Policy** with a `deployIfNotExists` effect plus a **remediation task** can switch settings on across many subscriptions at once.

See the Foundations pages listed above, especially *defender-for-cloud-basics*.

## In one sentence

Workload protection (CWP, also called CWPP) plans are the per-workload threat-detection switches in Defender for Cloud: you turn each one on at a scope, tune its settings and extensions, and it starts raising the alerts you used to triage.

## Why it exists

CSPM tells you the window is unlocked. CWP tells you someone is climbing through it right now. As an analyst you saw "Detection source: Defender for Storage" on an incident. That alert existed only because an engineer enabled the Storage plan on that subscription. No plan, no alert — the misconfiguration still shows in posture, but the attack is silent.

Think of a building: CSPM is the safety inspection, CWP is the alarm contract, signed separately for each floor type.

## What actually matters

**1. The plan catalogue.** Know what each plan protects and where its deep-dive lives.

| Plan | Protects | Installs on the resource? | Key settings | Deep dive |
|---|---|---|---|---|
| **Defender for Servers** (Plan 1 / ==@Plan 2==) | Azure VMs, Arc servers, AWS EC2, GCP VMs | ==@Yes== — MDE extension | Endpoint protection, vulnerability assessment, agentless scanning, FIM | D3.2.5–D3.2.7 |
| **Defender for Storage** | Blob, Azure Files, Data Lake Storage Gen2 | No | activity monitoring (always on), **malware scanning** add-on with monthly cap, sensitive data threat detection | D2.1.3 |
| **Defender for Databases** (bundle of four) | Azure SQL, SQL Server on machines, open-source relational (PostgreSQL, MySQL, MariaDB), Cosmos DB | Only SQL on machines (needs Arc off-Azure) | each sub-plan can be switched separately | D2.2.3 |
| **Defender for Containers** | AKS, EKS, GKE, Arc Kubernetes, registries | Yes — Defender sensor, Azure Policy for Kubernetes | sensor, registry access, K8s API access | D3.3.1 |
| **Defender for App Service** | App Service web apps and APIs | No | — (detects dangling DNS too) | D3.3.7 |
| **Defender for Key Vault** | unusual vault access | No | — | D1.2.7 |
| **Defender for Resource Manager** | management-plane operations (ARM) | No | — | this page |
| **Defender for APIs** | APIs published in **Azure API Management** | No | onboard APIs from Defender for Cloud or from the APIM instance | this page |
| **Defender for AI Services** | Azure OpenAI, Azure AI Model Inference | No | prompt evidence (`AIPromptEvidence`) | D3.1.8 |
| ==!Defender for DNS== | Azure-provided DNS queries | No | ==!not offered to new subscriptions== — included in Servers **Plan 2** since 1 August 2023 | — |

Defender CSPM appears in the same list but is posture, not workload protection (D4.1.1).

**2. Scope rules.**

| Scope | Which plans |
|---|---|
| Subscription / AWS account / GCP project | all plans — ==+recommended default== |
| Single resource | Servers **Plan 1** (enable), Servers P1 or ==!P2 (disable only)==, Storage, Azure SQL, open-source relational DBs |
| Log Analytics workspace | Defender for Servers, Defender for SQL Servers on Machines |
| Management group | via Azure Policy, or the Defender portal's plan management (preview) |

==!Only one Servers plan per subscription== at subscription level — the scale article says you can't enable both P1 and P2 on the same subscription; to use both, split subscriptions into two management groups and assign a policy to each. Resource-level settings override the subscription: the plan-selection article adds that with P2 on the subscription you can push individual machines down to P1 (or off) by API, script or Policy — but never up to P2 (D3.2.5). A disabled plan leaves its extensions installed; they stop collecting data.

**3. Enabling = toggle, settings, save.** Environment settings > *subscription* > **Defender plans** > toggle a plan **On** (or **Enable all**) > open **Settings** where shown > **Save**. Most plans deploy their components within minutes. A **30-day free trial** applies per plan, or until a plan's usage limit is reached. ==!Storage malware scanning is billed from day one==, outside the trial. Defender for AI Services' trial is capped at 75 billion tokens. Its overview says enabling it at subscription scope needs **Owner**; its enablement how-to says **Owner or Contributor** — two Microsoft pages disagree, so Owner is the safe answer. The free-trial article names **Security Admin or Owner** to enable a plan.

**4. Plan settings worth knowing.** Storage malware scanning defaults to a cap of ==@10,000 GB per storage account per month==; when the cap is hit, new uploads go unscanned until next month. Sensitive data threat detection is on by default at no extra cost. Turning **Databases** on enables all four sub-plans; each is priced separately and can be turned off individually.

**5. At scale.** Two documented routes beyond clicking per subscription:

- **Azure Policy at the management group.** The built-in *Configure Azure Defender for Servers to be enabled* (and siblings for other plans) uses `deployIfNotExists`; add a **remediation task** for existing subscriptions. *Enable Microsoft Defender for Cloud on your subscription* only registers subscriptions, with `pricingTier` defaulting to **free**. Azure Policy also gives the audit trail ("which subscription is non-compliant").
- **Defender portal plan management (preview).** Cloud security > Define Cloud Security plans: **Global plans enablement** (tenant) or per management group / subscription. Statuses are **Unconfigured (Inherit)**, **Enabled**, **Disabled**. **Enforce and lock** stops child scopes overriding. Moving an environment here switches billing to **Defender workload units (DWU)** and ==!drops resource-level settings==. Azure commercial only — AWS and GCP stay in the Azure portal. Needs **Security Administrator** (Entra) or **Core security settings (Manage)**, plus **Owner** or **User Access Administrator** to connect the environment.

> **Contradiction — product docs win.** Unit 5 says you select a management group in Azure portal Environment settings and toggle plans there. The product docs document management-group enablement through **Azure Policy** or the **Defender portal** (preview); per-plan toggles in the Azure portal are per subscription or connector.

**6. Verify.** The **Coverage workbook** (Defender for Cloud > Workbooks) shows Relative coverage, Absolute coverage, Detailed coverage and Additional information, filterable by Azure, AWS or GCP.

## Where it lives

- **Azure portal** > Microsoft Defender for Cloud > **Environment settings** > *subscription* > **Defender plans** (toggles, **Enable all**, **Settings**, Monitoring coverage column).
- **Azure portal** > Policy > Definitions > *Configure Azure Defender for … to be enabled* > Assign at management group > Remediation.
- **Defender portal** > Cloud security > **Define Cloud Security plans** (preview).

```bicep
// Subscription-scope deployment: Storage plan with a malware scanning cap
// (shape from Microsoft's IaC enablement sample; the cap is a string)
targetScope = 'subscription'
resource storagePlan 'Microsoft.Security/pricings@2023-01-01' = {
  name: 'StorageAccounts'
  properties: {
    pricingTier: 'Standard'
    subPlan: 'DefenderForStorageV2'
    extensions: [
      { name: 'OnUploadMalwareScanning', isEnabled: 'True'
        additionalExtensionProperties: { CapGBPerMonthPerStorageAccount: '5000' } }
      { name: 'SensitiveDataDiscovery', isEnabled: 'True' }
    ]
  }
}
```

## Exam traps

- "Protect only three production VMs with Plan 2" → ==!not possible per resource==. Enable P2 on the subscription and disable it on the others, or move the VMs.
- "Run P1 for dev and P2 for prod" → separate **subscriptions** (two management groups, one policy each) is the documented design; a per-machine P1 override inside a P2 subscription also works (D3.2.5).
- "New subscriptions must get the Servers plan automatically" → Azure Policy DINE at the **management group** (or Defender portal inheritance).
- "Stop someone switching a plan off below" → Defender portal **Enforce and lock**, or Azure Policy compliance + remediation.
- "DNS tunnelling alerts on a new subscription" → **Defender for Servers Plan 2**, not a separate DNS plan.
- "Protect APIs" → only APIs in **Azure API Management**.
- "Malware scanning stopped mid-month" → monthly **cap** reached.
- ==!"Disabling a plan removes its agent."== Extensions stay; they stop collecting.
