## Azure first

- **Microsoft Foundry** is Azure's platform for AI apps. A **Foundry resource** is the Azure resource; **projects** live inside it. A **model deployment** (for example a GPT model) is the endpoint your apps call.
- **Azure API Management (APIM)** is a managed reverse proxy for APIs. Callers hit APIM; APIM runs **policies** (small XML rules) on each request and forwards it to a **backend**. It comes in classic tiers and **v2 tiers** (Basic v2, Standard v2, Premium v2).
- A **token** is the unit a language model reads and writes (roughly four characters of English). Models are billed and throttled in **tokens per minute (TPM)**, not in calls.
- A **managed identity** is an Entra ID identity that Azure gives a resource, so the resource can get tokens without a stored secret.

See the Foundations pages listed above: API Management, Foundry, AI agents and MCP, Entra ID, RBAC, diagnostic settings.

## In one sentence

The AI Gateway is a set of AI-specific APIM policies and features — token limits, token metrics, semantic caching, content safety, load balancing — that sit in front of Foundry model deployments, agents and MCP tools so every AI call passes one checkpoint.

## Why it exists

Picture five apps sharing one model endpoint and one API key. You can't tell who called. One leaked key exposes everything. One runaway agent loop eats the whole TPM quota. Nothing is logged centrally.

As an analyst you have seen the wallet-attack and runaway-usage alerts. The gateway is the engineer's fix: a turnstile at the building entrance. Everyone shows their own badge, the turnstile counts how much each person takes, and the guard log records every entry.

Agents make this urgent. One agent can call a model dozens of times per user request, in bursts nobody predicted.

## What actually matters

1. **In APIM it is not a separate product.** The AI gateway is a set of capabilities inside APIM's existing gateway. It works in all APIM tiers, but feature availability varies by tier. It fronts OpenAI-compatible APIs, Foundry models, non-Microsoft providers (for example Amazon Bedrock), remote **MCP servers** and **A2A agent APIs**.
   - ==!Name clash:== Microsoft has also launched a standalone **AI Gateway (preview)** product — a different resource type (`Microsoft.ApiManagement/aigateways`, versus `Microsoft.ApiManagement/service` for APIM), its own portal, public preview in East US 2 and Sweden Central only. This bullet tests the ==+APIM-based== gateway that Foundry's **Manage > AI Gateway** pane creates.

2. **Two ways in — Foundry portal or APIM.**
   - **From Foundry (preview):** Foundry portal **Manage > AI Gateway > Add AI Gateway**, pick the Foundry resource, then **Create new** (deploys a ==@Basic v2== APIM instance, meant for dev/test) or **Use existing**. An existing instance must be in the same tenant **and** subscription, in a ==@v2 tier==, and you need **API Management Service Contributor** (or Owner) on it. Creating one needs **Contributor** or **Owner** on the resource group.
   - The gateway is enabled at the ==@Foundry resource level==, not per project. New projects join automatically; ==!existing projects must be added== with **Add project to gateway**.
   - **From APIM directly:** import the Foundry or Azure OpenAI API with the wizard, which sets up managed identity auth and can pre-configure policies. Custom policies, networking and federated gateways are always done in APIM.

3. **Token limits, not call limits.** `llm-token-limit` (generic) and `azure-openai-token-limit` (the Azure OpenAI-specific form) cap tokens per `counter-key` — usually the subscription ID, an IP, or a policy expression. Exceeding `tokens-per-minute` returns ==@429 Too Many Requests==. Exceeding `token-quota` over a period (hourly to yearly) returns ==@403 Forbidden==. In the Foundry portal the same limits are set **per project per model deployment**.

4. **Content safety at the gateway.** `llm-content-safety` sends prompts (inbound) or completions (outbound) to an **Azure AI Content Safety** resource. It checks the categories `Hate`, `SelfHarm`, `Sexual`, `Violence` against a threshold, custom blocklists, and — with `shield-prompt="true"` — prompt attacks. A hit returns **403**. APIM's managed identity needs **Cognitive Services User** on the Content Safety resource.

5. **Managed identity to the backend.** Enable APIM's system-assigned identity. Grant it **Cognitive Services OpenAI User** on the Azure OpenAI/Foundry resource. Set the backend credential to managed identity with resource `https://cognitiveservices.azure.com/`. Strip any caller `api-key` header with `set-header`. Revoke the role and every call through APIM stops.

6. **Cost, resilience, observability.**
   - **Semantic caching:** `llm-semantic-cache-lookup` / `llm-semantic-cache-store` reuse answers to similar prompts. Needs an **embeddings model deployment** and **Azure Managed Redis** (or another RediSearch cache).
   - **Load balancing** across backends: round-robin, weighted, priority-based, session-aware. Use priority to drain PTU first.
   - **Circuit breaker:** stops sending to an unhealthy backend; trip duration can follow the backend's `Retry-After` header.
   - **Token metrics:** `llm-emit-token-metric` sends token counts to Application Insights with custom dimensions.
   - **Logs:** diagnostic setting **Logs related to ApiManagement Gateway** to Log Analytics; query the ==@ApiManagementGatewayLogs== table. Default logging is metadata only. Logging prompt/completion bodies is opt-in and captures sensitive text.

### Which policy does what

| Need | Policy / feature | Response when it trips |
|---|---|---|
| Cap tokens per minute per caller | `llm-token-limit` `tokens-per-minute` | ==@429== |
| Cap total tokens per period | `llm-token-limit` `token-quota` + `token-quota-period` | ==@403== |
| Block harmful or attack prompts | `llm-content-safety` (+ `shield-prompt`) | **403** (streaming: stream stops, no 403) |
| Cheaper repeat answers | `llm-semantic-cache-lookup` / `-store` | cached completion |
| Per-consumer token chargeback | `llm-emit-token-metric` | metric in App Insights |
| Survive a slow or failed backend | backend pool load balancer + circuit breaker | traffic shifts |
| No keys to the model | backend credential = managed identity | — |

## Where it lives

- **Foundry portal** (`ai.azure.com`, New Foundry toggle on): **Manage > AI Gateway > Add AI Gateway**; select the gateway name to **Add project to gateway** / **Remove project from gateway**; token limits on the same pane.
- **Azure portal > API Management services > *instance***: **APIs** (import Foundry API), **Backends** (load balancer pool, circuit breaker, managed identity credential), **APIs > *API* > Inbound processing** (policies), **Security > Managed identities**, **Monitoring > Metrics / Diagnostic settings / Logs**.

```xml
<inbound>
  <base />
  <llm-token-limit counter-key="@(context.Subscription.Id)"
      tokens-per-minute="500" estimate-prompt-tokens="false"
      remaining-tokens-variable-name="remainingTokens" />
  <llm-content-safety backend-id="content-safety-backend" shield-prompt="true">
    <categories output-type="EightSeverityLevels">
      <category name="Hate" threshold="4" />
      <category name="Violence" threshold="4" />
    </categories>
  </llm-content-safety>
</inbound>
```

## Exam traps

- ==!Rate limit by calls (`rate-limit-by-key`) is the wrong answer== for AI cost control. One call can burn thousands of tokens. The answer is ==+llm-token-limit / azure-openai-token-limit==.
- **429 vs 403.** 429 = per-minute rate exceeded, resets next window. 403 = the period quota is used up, or content safety blocked it.
- **APIM content-safety threshold runs the other way from Foundry.** In `llm-content-safety`, 0 is most restrictive and 7 least; content *below* the threshold passes. In Foundry guardrails, a **High** blocking level is the strictest ([D3.1.9](D3.1.9.html)).
- **"Create new" gives Basic v2** — dev/test. A private Foundry resource (public access disabled) needs a ==+Standard v2 or Premium v2 with a private endpoint, or Premium v2 VNet-injected== APIM. Classic tiers can't be picked from Foundry.
- **"Deploy the AI Gateway resource (`aigateways`)"** is the standalone preview product, ==!not== the APIM capability this bullet names. Foundry's pane creates or links an ==+APIM v2== instance.
- **Existing projects don't join the gateway automatically.** "Requests bypass the gateway" = project not added.
- **One gateway per Foundry resource.** Strict isolation between projects = separate Foundry resources, each with its own gateway.
- **Disable ≠ delete.** Removing a project stops routing it; the APIM instance keeps billing until you delete it.
- **Semantic caching needs two extras:** an embeddings deployment and an external Redis-compatible cache.
- **Foundry agents authenticate with their agent identity**, not the project managed identity; only *published* agents get a distinct identity ([D3.1.6](D3.1.6.html)).
- Backend API protection in general (JWT validation, IP filter, client certificates) is [D3.3.9](D3.3.9.html); this page is the AI-specific layer.
