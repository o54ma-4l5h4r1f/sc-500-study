## Azure first

- **Defender for Cloud** has posture plans (**CSPM** — "is it configured safely?") and workload plans (**CWP** — "is it under attack now?"). **Defender CSPM** is the paid posture plan; it adds attack paths, **Cloud Security Explorer** (a graph query tool) and **sensitive data discovery**.
- **Data resources** here means storage accounts, managed databases (Azure SQL, Cosmos DB…) and databases on VMs. **AI resources** means Foundry/Azure OpenAI, Azure Machine Learning — and, through connectors, Amazon Bedrock and Google Vertex AI.
- **Grounding** is feeding your own data (a storage account, an AI Search index) to a model so it answers from it. That data store is now part of the AI attack surface.
- A **resource provider** is the Azure service that owns a resource type; it must be **registered** on a subscription before that service works there.

See the Foundations pages listed above: Defender for Cloud basics, Foundry basics, storage accounts, RBAC.

## In one sentence

The Data and AI security dashboard is one Defender for Cloud page that shows every data and AI resource you own, how well each is covered by Defender plans, the worst alerts, recommendations and attack paths against them, and what sensitive data or internet exposure sits behind your AI apps.

## Why it exists

AI security findings are scattered: posture recommendations in CSPM, prompt alerts in the AI services plan, storage alerts in Defender for Storage, sensitive-data labels in Purview. An engineer needs one screen to answer three questions: *Is everything covered? What's worst right now? What data could leak through an AI app?*

Think of a building's security control room wall. One screen shows which floors have cameras (coverage), which alarms are ringing (alerts), and which doors are propped open to the street (internet exposure). You don't walk to each floor's guard desk.

As an analyst you lived in the incident queue. This dashboard is the engineer's weekly review — it tells you which subscription forgot to enable the plan *before* the incident.

The dashboard has no data of its own. It is a ==@view over the plans you enabled==. Missing plan = empty tile.

## What actually matters

1. **Prerequisites for the full view.** Enable ==@Defender CSPM== with its **sensitive data discovery** extension, **Defender for Storage**, **Defender for Databases** and **threat protection for AI workloads** (Defender for AI Services, [D3.1.8](D3.1.8.html)). Register the **Microsoft.Security** resource provider on each subscription. With only some plans the dashboard still opens, but shows partial data. The dashboard is enabled per subscription and reflects that subscription's plans.

2. **The four sections.**
   - **Data and AI security overview:** all resources per cloud, split into storage assets, managed databases, hosted databases (IaaS) and AI services; each marked **fully, partially or not protected** by Defender CSPM, Storage, Databases and AI threat protection.
   - **Top issues:** highest-severity alerts (by MITRE ATT&CK tactic), critical/high recommendations, critical/high attack paths.
   - **Data closer look:** sensitive data discovery (top info types and sensitivity labels), data threat protection alerts, data queries in security explorer, internet-exposed data resources.
   - **AI closer look:** **AI discovery** (all AI resources), **AI threat protection** (==@number of prompts scanned== and alerts by severity), AI queries in security explorer, and **internet-exposed resources used for grounding** (storage and search).

3. **AI-BOM — the AI bill of materials.** Defender CSPM continuously discovers deployed AI workloads in Azure OpenAI, Azure AI Foundry, Azure Machine Learning, **Amazon Bedrock** and **Google Vertex AI** — models, data, and app components "from code to cloud". It also flags vulnerable generative-AI libraries (TensorFlow, PyTorch, LangChain) in code and container images. Query it in **Cloud Security Explorer** with the template **AI workloads and models in use**.

4. **Agents moved licence.** ==!Effective July 1, 2026, AI agent discovery and posture for Foundry and third-party cloud agents need a Microsoft Agent 365 licence.== Defender CSPM still discovers Foundry accounts and projects. ==!Foundry agent data no longer appears in this dashboard or in Cloud Security Explorer==, and third-party cloud agents are no longer discovered through Defender for Cloud connectors (use Agent 365 registry sync). The agent inventory lives in the Defender portal under **Assets > AI agents** ([D3.1.5](D3.1.5.html)).

5. **Posture checks for AI.** Recommendations and IaC checks cover private endpoints for AI services, restricted endpoints, managed identity and identity-based (keyless) auth, diagnostic logs, CMK (only if required), and "content filtering should be used on model deployed in Microsoft Foundry" (preview). **Attack path analysis** chains them: an internet-exposed storage account with sensitive data used for grounding → an AI endpoint.

6. **Operational follow-through.** Weekly: check every AI subscription shows AI threat protection active. Confirm alerts reach Defender XDR (and Sentinel through the Defender XDR connector). Set **Environment settings > *subscription* > Email notifications** with a severity threshold of at least **High**. Suppress known red-team false positives with suppression rules.

## Where it lives

**Azure portal > Microsoft Defender for Cloud > Data and AI security** (left menu). From **Data closer look**: **View all managed databases alerts** / **View all storage alerts**. **Manage Sensitivity Settings** opens tenant-level data sensitivity settings (Purview info types and labels).

**AI-BOM query:** **Defender for Cloud > Cloud Security Explorer > AI workloads and models in use > Open query > Search.**

**Permissions:** `Microsoft.Security/assessments/read`, `Microsoft.Security/assessments/subassessments/read`, `Microsoft.Security/alerts/read`.

> **Contradiction — show both.** The product article names the minimum role as "**Security explorer**" (not a standard built-in Azure role name). The training unit says the minimum role is ==@Security Reader==. Security Reader carries all three read permissions above; treat **Security Reader** as the least-privilege answer and expect the product wording to be corrected.

## Exam traps

- **"Which plan do I need for the dashboard?"** Defender CSPM is the core (it's a CSPM feature in the support matrix, GA in commercial Azure, not in Azure Government). AI tiles need the AI services plan. ==!The AI services plan alone gives a partial dashboard.==
- **Prompts scanned** comes from Defender for AI Services, not from CSPM.
- **AI-BOM is CSPM, multicloud.** Bedrock and Vertex AI appear in discovery and posture — even though Defender for AI Services threat detection doesn't cover AWS.
- **Agent posture is Agent 365 now**, not Defender CSPM (from July 1, 2026). "Where do I see Foundry *agents* on the Data and AI dashboard?" → ==!you don't== any more; ==+Defender portal > Assets > AI agents==.
- **Dashboard ≠ Purview DSPM for AI.** Defender's dashboard is about Azure/multicloud *resources* and their exposure; Purview DSPM for AI is about *users' prompts* and Copilot data ([D3.1.2](D3.1.2.html)).
- **Sensitive data discovery is a Defender CSPM extension** — turn it on separately, or the Data closer look stays empty.
- **Microsoft.Security not registered** → missing assessments, even with plans paid for.

## Skip

- **The protect-workloads module's lifecycle diagram (DevOps → CSPM → CWP).** Know the three layers by name; the picture adds nothing testable.
- **Generic recommendation categories table in unit 4** (identity, network, data, dependencies). Recommendations in general are [D4.1.1](D4.1.1.html).
- **Alert classification and incident workflow in unit 3 of the AI services module.** Analyst ground.
- **The Defender portal "Cloud overview dashboard" Workload Insights tiles.** A different dashboard; not this objective.
- **AWS connector re-permissioning steps** for AI posture. Multicloud connectors are D4.1.
