## Azure first

- **Microsoft Defender for Cloud** checks how your Azure, AWS and GCP resources are configured. Its free tier, **Foundational CSPM**, is on for every subscription where Defender for Cloud is enabled. CSPM = cloud security posture management: "is it set up safely?".
- **Defender CSPM** is a *paid plan* you switch on per subscription, AWS account or GCP project, in **Environment settings > Defender plans**. It bills per resource (VMs, storage accounts, databases and so on).
- A **recommendation** is one misconfiguration on one resource ("storage account allows public network access"). You know these as an analyst. This page is about ranking them.
- Defender for Cloud now shows posture in two places: the **Azure portal** (`portal.azure.com`) and the **Defender portal** (`security.microsoft.com`), under *Cloud security* and *Exposure Management*.

See the Foundations pages listed above, especially *defender-for-cloud-basics*.

## In one sentence

Defender CSPM builds a map of how your cloud resources connect (the **cloud security graph**), then uses it to rank recommendations by real risk, to show **attack paths** an outside attacker could walk to your valuable data, and to let you query the map yourself in **cloud security explorer**.

## Why it exists

Foundational CSPM gives you a flat list: hundreds of recommendations, each with a fixed severity. Two storage accounts with the same public-access setting look identical, even if one holds patient records and the other holds test logs.

Think of a building inspector's report versus a burglar's route map. The report lists every unlocked window. The route map shows the one window next to the fire escape that leads to the safe. As an analyst you saw the burglary afterwards. Defender CSPM shows you the route before anyone walks it.

## What actually matters

**1. What the paid plan adds.** Know this table cold. Everything in the left half is free.

| Capability | Foundational CSPM (free) | Defender CSPM (paid) |
|---|---|---|
| Asset inventory, MCSB, secure score, recommendations, remediation tools | ==+Yes== | Yes |
| Workflow automation, data export, Azure Workbooks | ==+Yes== | Yes |
| ==@Cloud security graph== (context engine) | No | Yes |
| ==@Attack path analysis== (with choke points) | ==!No== | Yes |
| ==@Cloud security explorer== (risk hunting) | ==!No== | Yes |
| ==@Risk prioritization== (risk level, risk factors) | No — columns blurred | Yes |
| Internet exposure analysis, EASM outside-in data (D4.1.6) | No | Yes |
| Agentless VM vulnerability + secrets scanning (D3.2.7, D1.2.6) | No | Yes |
| Agentless Kubernetes discovery, agentless container image scanning | No | Yes |
| Data-aware posture: sensitive data discovery (DSPM) | No | Yes |
| AI security posture (AI BOM), API security posture | No | Yes |
| Critical assets protection | No | Yes |
| Governance rules, custom KQL recommendations (D1.3.3) | No | Yes |
| Regulatory compliance standards beyond MCSB (D4.1.2) | No | Yes — but ==!not CSPM-only==: any paid plan except Defender for Servers P1 / Defender for APIs P1 unlocks them |
| Code-to-cloud: DevOps PR annotations, code-to-cloud mapping | No | Yes |
| Serverless protection (Functions, Web Apps, Lambda) | No | Yes |

**2. Risk level is not severity.** Every recommendation has a fixed **severity** (Critical, High, Medium, Low) set by Microsoft. Defender CSPM adds a **risk level** per resource: ==@Critical, High, Medium, Low, Not evaluated==. Risk is calculated from **risk factors**: internet exposure, data sensitivity, lateral movement potential and attack path involvement. The same misconfiguration can be Critical on a public, sensitive resource and Low on a private test one. **Not evaluated** usually means the resource isn't covered by Defender CSPM. Risk prioritization ==!does not change the classic secure score==. The Defender portal's **Cloud Secure Score** is the risk-weighted model; the Azure portal keeps the classic, control-based score.

**3. Attack paths are external only.** The algorithm starts at an *external* entry point and follows real lateral movement (an attached managed identity with permissions, a network route) to a critical target. Each map shows:

| Element | Meaning |
|---|---|
| **Entry point** | where an outside attack starts (internet-exposed VM, public storage) |
| **Vulnerable node** | a resource whose weakness enables the next hop |
| **Choke point** | a node where several paths converge — the highest-leverage fix |
| **Target asset** | the crown jewel: sensitive database, AI endpoint |

Attack paths are rated ==@High, Medium or Low==. Select a node to see its **MITRE ATT&CK** tactics, risk factors and **Insights**. The Remediation tab splits fixes into **Recommendations** (break the path) and **Additional recommendations** (reduce risk, don't break it alone). A fixed path takes ==@up to 24 hours== to leave the list. An ==+empty attack path list is good news==, not a broken feature.

**4. Cloud security explorer is for your own questions.** Pick a resource type, add conditions with **+** (internet exposed, has high-severity vulnerabilities, has access to a storage account that contains sensitive data), then **Search**. Start from **query templates** at the bottom of the page (**Open query**). Results export with **Download CSV report**; **Share query link** copies a URL. It covers Azure, AWS and GCP. The graph is refreshed by daily **snapshot publishing**, so it is not real time. With only Defender for Servers **Plan 2**, you can query keys and secrets, but the full explorer needs Defender CSPM.

**5. Prerequisites that silently empty the graph.**

- Attack paths and the explorer need Defender CSPM ==@plus agentless scanning== (the concept article also accepts Defender for Servers vulnerability assessment).
- ==!Only a Subscription Owner== gets the agentless scanner switched on when enabling Defender CSPM. A lower role can enable the plan, but the scanner stays off and attack paths show no vulnerabilities.
- Container attack paths need the **Agentless discovery for Kubernetes** component (or Defender for Containers with its agents).
- Viewing attack paths and the explorer: **Security Reader, Security Admin, Reader, Contributor or Owner**. Limited permissions across subscriptions hide parts of a path by design.

**6. The plan's components.** After enabling, open **Settings** and toggle: agentless scanning for machines (with tag exclusions), agentless discovery for Kubernetes, agentless container vulnerability assessment, **sensitive data discovery** (samples data using Microsoft Purview sensitive information types), **CIEM** (cloud identity permissions, up to 24 hours to collect), serverless protection and serverless containers. **Critical assets protection** lets you tag crown jewels with classification rules; rules sync both ways with Microsoft Security Exposure Management, and creating them needs the Entra role **Security Operator** or higher. **AI security posture** discovers Azure OpenAI, Foundry, Azure Machine Learning, Amazon Bedrock and Google Vertex AI workloads into an **AI BOM** (bill of materials). From 1 July 2026, agent-level discovery for Foundry agents needs a Microsoft Agent 365 licence.

## Exam traps

- "See which misconfigurations an internet attacker could chain to reach a database" → ==+attack path analysis== (Defender CSPM). Not secure score, not regulatory compliance.
- "Ask an ad-hoc question: which VMs with high-severity CVEs can reach sensitive storage?" → ==+cloud security explorer==. Attack paths are automatic; the explorer is your query.
- "One fix that breaks the most paths" → the ==@choke point==.
- "Risk level and risk factor columns are blurred" → Defender CSPM isn't enabled on that scope.
- "Defender CSPM enabled but attack paths show no vulnerabilities" → enabled by a non-Owner, so agentless scanning is off.
- ==!"Attack paths list is empty, so the feature is broken."== Empty means no confirmed externally exploitable path.
- ==!"Severity and risk level are the same."== Severity is fixed per recommendation; risk is per resource and context.
- ==!"Foundational CSPM includes attack paths."== It includes secure score, MCSB and recommendations only.
- Attack paths use **three** levels (High/Medium/Low). Recommendation risk uses **five** (Critical/High/Medium/Low/Not evaluated).
