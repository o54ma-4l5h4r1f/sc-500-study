## Azure first

- **Azure Container Registry (ACR)** is a private store for container images, reached at `<name>.azurecr.io`. Images live in **repositories** (for example `retail/checkout`), versioned by **tags**.
- ACR has three **SKUs** (tiers): **Basic**, **Standard**, **Premium**. Most network-isolation features are ==@Premium-only==.
- Two planes: the **control plane** (Azure Resource Manager — create, configure, assign roles) and the **data plane** (push and pull images). Roles are split the same way.
- A **private endpoint** gives a PaaS service a private IP in your VNet; **private DNS** makes the normal name resolve to it.

See the Foundations pages listed above, especially *containers-and-kubernetes-basics* and *azure-rbac-and-entra-roles*.

## In one sentence

Securing ACR means: turn the shared admin account off, give each workload the smallest Entra role (pull vs push), use scope-map tokens only where Entra can't be used, keep the registry off the internet with a Premium private endpoint or IP rules, keep anonymous pull off, sign images with Notation, and let Defender for Containers scan what's stored.

## Why it exists

The registry is the supply line for every cluster. Whoever can push to it can run code in production. Whoever can pull from it can copy your software and find secrets baked into images. Think of a pharmacy stockroom: one shared key for everyone (admin account) is the worst case. Badges per person (Entra roles), a locked side door only staff can reach (private endpoint) and tamper-evident seals on every box (image signing) are the fix.

## What actually matters

**1. Admin user: off.** One username and two passwords with full push/pull on the whole registry, not tied to any Entra identity. It is ==@disabled by default==; keep it that way (`az acr update --admin-enabled false`). Move workloads to managed identity *before* disabling, or pulls break.

**2. Entra roles — and the mode switch.** A registry has a **Role assignment permissions mode** (Properties blade):

| Mode | Data-plane roles that work |
|---|---|
| **RBAC Registry Permissions** (legacy default) | ==@AcrPull==, ==@AcrPush==, ==@AcrDelete== (registry-wide) |
| **RBAC Registry + ABAC Repository Permissions** | ==@Container Registry Repository Reader / Writer / Contributor==, optional ABAC conditions to scope to repositories; **Container Registry Repository Catalog Lister** to list repositories |

==!In ABAC mode, AcrPull/AcrPush/AcrDelete are ignored.== Switching mode without reassigning roles cuts workloads off. Least privilege: AKS, Container Apps and ACI get a **pull** role; CI/CD gets a **push/write** role; nobody running workloads gets **Contributor**. Assigning roles needs **Owner** or **Role Based Access Control Administrator** on the registry. Control-plane admins without data access: *Container Registry Contributor and Data Access Configuration Administrator*.

**3. Tokens and scope maps.** A **scope map** lists repository actions (`content/read`, `content/write`, `content/delete`...). A **token** bound to it gets up to two passwords. Use for clients that can't use Entra (IoT devices, external partners). ==!Tokens aren't Entra identities==: no Conditional Access, no PIM. Store passwords in Key Vault, set expiry, rotate.

**4. Network isolation.**

- **Private endpoint** (==@Premium==): registry gets a private IP; turn **public network access** off. A dedicated data endpoint is created automatically.
- **Public IP network rules** (==@Premium==): default action **Deny** plus allowed CIDRs, max **200** rules. Rules ==!don't apply to private endpoint traffic==.
- **Trusted services** bypass (on by default when you restrict the network) lets selected Azure services — including **Defender for Cloud** (for scanning) and ACI — reach a locked registry. Some need a managed identity and role.
- Turning public access off also blocks **Microsoft-hosted Azure DevOps agents**; use self-hosted agents in the VNet.

**5. Anonymous pull: off.** `--anonymous-pull-enabled` (Standard and Premium) makes ==!every repository== publicly pullable, overriding token or ABAC repository permissions. Default is off. Enable only for deliberately public content.

**6. Image signing: Notation, not DCT.** ==!Docker Content Trust is deprecated==: no new enablement since **May 31, 2026**; removal **March 31, 2028**. The replacement is **Notary Project / Notation** with signing keys in Key Vault, verified in pipelines or on AKS with **Ratify + Azure Policy**. The **AcrImageSigner** role belongs to the DCT model.

**7. Scanning.** Vulnerability scanning of stored images is **Defender for Containers** (Registry access component, see D3.3.1). Also available: Premium **customer-managed key** encryption (set at creation), **image locks** (`writeEnabled`/`deleteEnabled` false), and **export policy** disabled to stop images being copied out.

## Where it lives

- **Azure portal > Container registries > *registry* > Settings > Access keys** (Admin user).
- **> Access control (IAM)** (role assignments); **> Settings > Properties** (role assignment permissions mode).
- **> Repository permissions > Scope maps / Tokens**.
- **> Settings > Networking** — **Public access** tab (All networks / Selected networks / Disabled, Firewall, trusted services) and **Private access** tab (private endpoints).

```bash
az acr update -n contosoacr --admin-enabled false --anonymous-pull-enabled false
az role assignment create --assignee <mi-principal-id> --role AcrPull --scope <acr-id>
az acr scope-map create -r contosoacr -n checkout-push --repository retail/checkout content/write content/read
az acr token create -r contosoacr -n checkout-ci --scope-map checkout-push
az acr update -n contosoacr --default-action Deny --public-network-enabled false
```

## Exam traps

- "AKS must pull images, least privilege" → ==+AcrPull== (or Repository Reader in ABAC mode), via `--attach-acr` or managed identity. Contributor and admin user are distractors.
- "Pipeline may push only to `retail/checkout`" → ABAC-conditioned **Repository Writer** (Entra) or a **scope-map token** (non-Entra). Plain AcrPush is too broad.
- Registry switched to ABAC mode, pulls fail with AcrPull assigned → ==!legacy roles not honoured==.
- "Restrict registry to office IPs on Standard SKU" → ==!not possible==; IP rules and private endpoints need **Premium**.
- Locked-down registry and Defender stops scanning → enable **Allow trusted Microsoft services**.
- "Enable content trust on a new registry today" → ==!not possible after May 31, 2026==; use Notation.
- Anonymous pull "only for the public repo" → it's registry-wide; use a separate registry.

## Skip

- **Skip:** geo-replication, zone redundancy, connected registries and artifact streaming. Availability features, not security bullets.
- **Skip:** the DCT `docker trust sign` workflow. Retiring; know only that it's being replaced.
- **Skip:** the full ABAC condition syntax and wildcard repository patterns. Know that conditions scope a role to repositories.
- **Skip:** the long control-plane permission lists per role in the roles directory. Know Reader/Writer/Contributor and the legacy trio.
- **Skip:** dedicated data endpoint FQDN formats and client-firewall service tags. Know they exist for outbound-filtered clients.
- **Skip:** ACR Tasks network-bypass policy beyond "disable unless a task needs it".

**Where the training module and product docs disagree (product docs win):**

- Unit 2 says IP firewall rules are the fallback "when using the Basic or Standard SKU". The product docs say ==!IP network rules require Premium==, same as private endpoints.
- Unit 2 shows enabling Docker Content Trust as current practice. The product docs say DCT ==!can't be enabled on new registries from May 31, 2026== and is removed March 31, 2028.
