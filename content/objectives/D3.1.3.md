## Azure first

- **Copilot Studio** is Microsoft's low-code agent builder. Agents live in a **Power Platform environment** (a container for apps, data and agents), managed in the **Power Platform admin center** (`admin.powerplatform.microsoft.com`).
- A **tool** is an action the agent can call: a connector, a SharePoint lookup, an email send, an MCP server. **Generative orchestration** means the model decides which tool to call.
- An **app registration** with a **federated identity credential (FIC)** lets one service prove who it is to another without storing a secret.
- The **Defender portal** (`security.microsoft.com`) is where the alerts, the **AI agents** inventory and **Advanced hunting** live.
- **Licence:** `license_blocked`. From ==@July 1, 2026== Copilot Studio agent security in Defender needs a ==@Microsoft Agent 365== licence (included in Microsoft 365 E7; add-on to E5). You also need Copilot Studio and Power Platform. Portal tour only.

New to these? Read the Foundations pages listed in "Before you start".

## In one sentence

Real-time protection makes a Copilot Studio agent ask Microsoft Defender "may I?" before every tool call, and Defender can block the call before it runs.

## Why it exists

As an analyst you met prompt injection only after the damage: an alert, an incident, a clean-up. An agent can be tricked into emailing a secret to an attacker in one turn. By the time a near-real-time alert fires, the email is gone.

Think of a bank teller who must phone the security desk before handing over cash above a limit. The teller (the agent) still serves customers. The security desk (Defender) sees the request, the customer and the reason, and can say no. If the phone line is dead for more than one second, the bank's policy decides whether the teller pays out anyway.

Copilot Studio already blocks user prompt injection (UPIA) and cross-domain prompt injection (XPIA) by default. Real-time protection adds an external check on top.

## What actually matters

**1. Three layers, only one is "real-time".**

| Layer | What it does | When |
|---|---|---|
| Discovery + posture | Finds agents, their tools and knowledge, risk level (D3.1.5) | after enablement |
| Detection | Alerts from agent observability logs (prompt injection, secret leakage) | near-real-time, after the action |
| ==@Real-time protection== | Inspects each tool call and can ==+block before it executes== | during the run |

**2. Two people, two portals — the handshake.** Neither the security engineer nor the Power Platform admin can finish alone.

| Step | Who | Where |
|---|---|---|
| Onboard to Agent 365; Security for AI on; connect the **Microsoft 365 connector** | Security Administrator | Defender portal > Settings > Security for AI > Get started |
| Copy the Defender endpoint URL | Security Administrator | Defender portal, Security for AI settings |
| Create an Entra app registration with an FIC (script `Create-CopilotWebhookApp.ps1` or manual) | admin with app-registration rights | Entra / Azure portal |
| Turn on threat detection for each environment, enter **App ID** + endpoint, set error behavior | ==@Power Platform Administrator== | Power Platform admin center > Security > Threat detection > Additional threat detection |
| Enter the same App ID; check status shows ==+Connected== | Security Administrator | Defender portal |

The proxy **App ID** is ==!not the agent's own Entra Agent ID==. It identifies the trusted Defender connection.

**3. Behaviour you must know.**

- Called ==!only for generative orchestration agents==; classic agents are skipped.
- Configured ==!per environment==. No tenant-wide switch, no PowerShell to push it. New environments need it turned on again.
- If Defender doesn't answer within ==@one second==, the default is ==!allow==. Change **Set error behavior** to **Block the query** for tighter control.
- Data sent per tool call: the recent prompt and chat history, previous tool outputs, agent/user/tenant identity, the tool, its inputs and the agent's reasoning.
- Applies to ==@new sessions== only. Users mid-conversation may need to restart.
- Without the Microsoft 365 connector, blocking still works but ==!alerts and incidents don't appear== in Defender.

**4. Rules: audit first, then block (current product).** In `Settings > Security for AI > Policies & rules > Real-time protection`, a built-in **Default** rule ==@audits== all agents (records matches, doesn't stop them). **Custom rules** ==+block== chosen detection types for all or selected agents. Detection types: **Secret exfiltration**, **Malicious content propagation**, **Evasion techniques**, **Unsafe email domain** (checked only at the tool-request point). The exclusion picker lists only agents with an Entra agent ID. Audits and blocks are written to the ==@`BehaviorInfo`== table. Once a blocking rule covers an agent, ==!near-real-time alerts stop for that agent== — you hunt the behaviors instead. **Prompt evidence collection** (on by default) puts redacted prompt snippets in alerts.

**5. Verify it works.** Defender portal **Assets > AI agents** shows the agent; Copilot Studio's **Agents** page shows a **Protection status** column (**Protected**, **Needs review**, **Unknown**); **Incidents & alerts** shows blocks; Advanced hunting shows activity:

```kusto
CloudAppEvents
| where Application == "Microsoft Copilot Studio"
| where Timestamp > ago(1h)
| project Timestamp, AccountDisplayName, ActivityType, ActivityObjects
```

**6. Don't confuse with Defender for AI Services.** Copilot Studio protection = Defender portal, agent tool calls. **Defender for AI Services** = a Defender for Cloud plan in the Azure portal for Azure OpenAI and Foundry Models (D3.1.8). Enabling one ==!doesn't enable the other==.

## Where it lives

- **Defender portal:** Settings > Security for AI (Get started; Policies & rules > Real-time protection; Prompt evidence collection).
- **Power Platform admin center:** Security > Threat detection > Additional threat detection > *environment* > Set up > **Allow Copilot Studio to share data with a threat detection provider**.
- **Copilot Studio:** Agents page > Protection status; Settings > Advanced > Metadata shows the agent's Entra Agent ID.

## Exam traps

- **"Security engineer enables it alone in Defender."** ==!No== — a ==+Power Platform Administrator== must configure each environment.
- **Defender times out** → default ==!allow==. To fail closed, set ==+Block the query==.
- **New environment unprotected** → it's ==+per environment==; turn it on again.
- **Blocks happen but no incidents** → ==+Microsoft 365 connector== not connected.
- **Classic (non-generative) agent not inspected** → by design.
- **App ID = agent identity.** ==!No== — it's the Defender connection's app.
- **"Enable the AI services plan in Defender for Cloud to protect Copilot Studio agents."** ==!Wrong product.==
- **Status Pending/Disconnected** → App ID mismatch or Power Platform side unfinished.

> **Contradictions — training module vs product docs (product wins).** (1) The module's Power Platform path is *Security > Threat Protection > Microsoft Defender - Copilot Studio AI Agents*; the Copilot Studio doc says *Security > Threat detection > Additional threat detection*. (2) The module implies Defender blocks suspicious calls automatically; the current Defender doc says the **Default** rule only ==!audits== and you create custom rules to block. (3) The module queries `AIAgentsInfo`; that table is being replaced by ==@`AgentsInfo`== under the Agent 365 transition. (4) The module says Defender for Cloud Apps licences cover this; from July 1, 2026 the transition doc lists Copilot Studio discovery, threat detection and real-time protection as needing an **Agent 365** licence. The same doc also says real-time protection "through Defender for Cloud Apps remains unchanged for tenants that continue using this experience" — for exam answers, pick ==+Agent 365==. On July 1, 2026 all Security for AI settings also collapse into one **Security for AI Agents** toggle; Agent 365 trials are 25 seats for 30 days. Preview status: Copilot Studio real-time protection is marked **Preview** in the Defender doc, and the Copilot Studio external threat detection article is prerelease.

## Skip

- **Skip:** building your own threat detection web service (the developer webhook interface). Know "bring your own protection" exists.
- **Skip:** the FIC subject-string base64 recipe and the AADSTS troubleshooting table. Know an Entra app with a federated credential is required.
- **Skip:** Foundry agent and Agent 365 Work IQ MCP coverage of real-time protection. Other agent types; name-level only.
- **Skip:** local agent runtime protection in Defender for Endpoint. Different product path.
- **Skip:** the module's Contoso alert names ("AI agent policy violation") and its "more than 100 files" example. Story, not product facts.
