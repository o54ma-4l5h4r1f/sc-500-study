## Azure first

- **Microsoft Purview** is Microsoft's data-protection suite. It lives in its own portal, `purview.microsoft.com` — not the Azure portal, not the Defender portal.
- **Sensitivity labels** tag files ("Confidential"). **Sensitive information types (SITs)** are patterns Purview spots in text (credit card numbers, passport numbers). **DLP** policies act on both.
- **Purview Audit** is the Microsoft 365 audit log. Copilot prompts and responses land there as events.
- A **collection policy** tells Purview which AI prompts and responses to capture from apps that don't feed Audit automatically.
- **Licence:** `license_blocked`. Product docs and the training module agree: ==@Microsoft 365 E5 or Microsoft Purview Suite== (formerly Microsoft 365 E5 Compliance); E3 doesn't qualify. Copilot data needs Microsoft 365 Copilot licences on the users. You can't run this in an Azure-only subscription — use the screenshots.

New to these? Read the Foundations pages listed in "Before you start".

## In one sentence

Purview Data Security Posture Management (DSPM) shows which sensitive data your AI tools touch — Copilot prompts and answers, agents, and third-party AI sites in a browser — and offers one-click policies to watch or block it.

## Why it exists

As an analyst you saw DLP alerts when someone emailed a credit-card list outside the company. AI adds a new exit door. A user pastes a confidential contract into a consumer chatbot. Copilot summarizes a "Highly Confidential" file into a chat answer. An agent reads a whole HR library. None of this looks like classic exfiltration, so classic DLP reports miss it.

DSPM is the CCTV room for AI. It doesn't lock doors by itself. It shows who carried what through which AI door, so you can decide which doors need a lock (DLP) and which drawers need relabeling.

## What actually matters

**1. The name changed — know both.** Microsoft now has a single **Data Security Posture Management** (`Solutions > DSPM`). The older **DSPM for AI (classic)** and **DSPM (classic)** still work, but ==!new features land only in the new DSPM==. The training module teaches the classic one. Same engine, same policies, different menus.

| Classic DSPM for AI | New DSPM |
|---|---|
| Overview > Get started, Recommendations | Setup tasks, **Objectives** (e.g. *Prevent data exposure in Microsoft 365 Copilot and Microsoft Copilot interactions*) |
| Reports | Posture, Reports |
| Apps and agents | Discover > Apps and agents; **AI observability** (includes Agent 365 agents, last 30 days) |
| Activity explorer | Discover > Activity explorer (**AI activities** tab) |
| Data risk assessments | Discover > Data risk assessments (D3.1.1) |
| Policies | Tasks and actions > Remediation actions |

**2. Prerequisites by AI source.** This table is the exam.

| Source | What you need |
|---|---|
| Microsoft 365 Copilot, Copilot Chat, agents | ==@Purview Audit on== (default for new tenants) + users with ==@Microsoft 365 Copilot licences== |
| Copilot in Fabric, Security Copilot | a ==@collection policy== (*Secure interactions for Microsoft Copilot experiences*) + enterprise Purview data governance. Without it you get audit events but ==!not prompts and responses== |
| Enterprise AI apps (ChatGPT Enterprise, Entra-registered, Foundry apps) | collection policy; Entra-registered apps integrate the Purview SDK; ==@pay-as-you-go billing== for AI apps other than Microsoft 365 Copilot |
| Third-party AI sites (ChatGPT consumer, Gemini) | ==@devices onboarded to Purview== + ==@Microsoft Purview browser extension== (Chrome); an Edge configuration policy for Edge |
| AI over the network (SASE/SSE) | collection policy *Detect sensitive info shared with AI via network* + a SASE/SSE integration added in DLP settings |

Sensitivity labels aren't required, but without them you get far fewer insights. Allow ==@24 hours== after creating policies before data shows.

**3. Activity explorer events.** **AI interaction** (prompt and response captured), **AI website visit** (user browsed to an AI site), **Sensitive info types** (SIT found in an AI interaction), **DLP rule match**. For browser-based events you see SIT and site, ==!not file names==. Seeing prompt text needs extra Purview permissions.

**4. One-click policies (classic names).** Discovery: DLP *Detect sensitive info added to AI sites* (audit only), Insider Risk *Detect when users visit AI sites*, Insider Risk *Detect risky AI usage*, Communication Compliance *Unethical behavior in AI apps*, collection policies for Copilot experiences, enterprise AI apps, network and Edge prompts. Protection: DLP *Block sensitive info from AI sites* (Adaptive Protection, block with override, test mode), DLP *Protect sensitive data from Copilot processing* (Copilot and agents won't process items with chosen labels), plus default sensitivity labels. Each policy is created in its home solution and edited there.

**5. DSPM watches; DLP blocks.** ==!DSPM doesn't block anything by itself.== To stop a paste into ChatGPT you need an **endpoint DLP** policy (or the one-click block policy). To stop Copilot using a label you need a **DLP policy for the Microsoft 365 Copilot location**.

**6. Risk triage.** The module ranks: highest = Highly Confidential content pasted into an external AI site; then Copilot output of Highly Confidential content shared externally; medium = Confidential content used inside the organization; low = Internal content. Interaction risk ≠ policy violation — it means review.

## Where it lives

| Task | Path | Role |
|---|---|---|
| Open new DSPM | Purview portal > Solutions > **DSPM** | Compliance Administrator (Entra) or Purview Compliance Administrator role group |
| View only (reports, activity) | same | Purview Security Reader role group, Data Security Viewer, Purview Data Security AI Viewer, Entra ==@AI Administrator==; prompt/response text needs ==@Purview Data Security AI Content Viewer== |
| Open classic | Purview portal > Solutions > **DSPM for AI (classic)** | same |
| Edit a one-click DLP / IRM / CC policy | its own solution (Data Loss Prevention, Insider Risk Management, Communication Compliance) | that solution's admin |

With **administrative units**, only an unrestricted admin can create the one-click policies that apply to everyone. If nobody in the tenant opens DSPM for ==@60 days==, Microsoft pauses the Microsoft 365 data refresh; it resumes (with a delay) when an admin returns.

## Exam traps

- **"DSPM for AI blocks pastes into ChatGPT."** ==!No== — it shows them. Blocking needs ==+endpoint DLP== (or the one-click block policy).
- **No Security Copilot prompts visible** → missing ==+collection policy==. Audit alone gives events without content.
- **No third-party AI site data** → devices ==+not onboarded== or ==+browser extension missing==.
- **No Copilot data at all** → check ==+Audit is on== and users ==+have Copilot licences==.
- **E3 is enough.** ==!No== — ==+E5 or Purview Suite==.
- **Sensitivity labels are a hard prerequisite.** ==!No== — recommended; SITs still work.
- **Which portal?** ==@Purview portal==. Not Defender, not Microsoft 365 admin center.

> **Contradiction — training module vs product docs.** The module says the **Get started** section offers three one-click policies (*Detect risky AI usage*, *Unethical behavior in AI apps*, *Detect sensitive info shared with AI via network*). The product doc's Get started section lists prerequisites instead (turn on Audit, install the browser extension, onboard devices, *Extend your insights*); those policies sit under **Recommendations**. The doc also states the classic version "is now replaced" by the new DSPM, while the module calls classic "fully functional". Follow the product: learn the new DSPM menus, recognise classic names.

## Skip

- **Skip:** Fabric data risk assessments and their Entra app setup. Not Copilot interaction risk.
- **Skip:** the Insider Risk Management and Communication Compliance policy internals. Know which one-click policy lands in which solution.
- **Skip:** Compliance Manager regulatory templates (*Get guided assistance to AI regulations*). Compliance work, not data-risk detection.
- **Skip:** Security Copilot prompts and Data Security Posture Agent inside DSPM. Nice helpers; the bullet tests what DSPM shows and what it needs.
- **Skip:** Data Security Investigations and proactive AI insights on the exfiltration objective. Investigation tooling beyond this bullet.
- **Skip:** the partner integrations (Varonis, Cyera, BigID, OneTrust) and Sentinel data lake setup for non-Microsoft sources. Name-level only.
- **Skip:** known issues in Activity explorer (Facilitator notes, missing mailboxes). Operational trivia.
