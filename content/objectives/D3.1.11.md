## Azure first

- A **Microsoft 365 tenant** is your organisation's Microsoft 365 instance (mailboxes, Teams, SharePoint, Copilot). The **Microsoft 365 admin center** (`admin.microsoft.com`) is its control panel — a different portal from the Azure portal.
- An **agent** is an AI assistant that can answer and act for users. Agents come from Microsoft, partners, **Copilot Studio**, **Agent Builder** in Copilot, SharePoint and **Microsoft Foundry**.
- **Microsoft Agent 365** is Microsoft's governance layer for agents. Its admin screens are the **Agents** section of the Microsoft 365 admin center.
- Admin rights here are **Entra roles** (AI Administrator, AI Reader), not Azure RBAC.

**Licence-blocked:** this needs a Microsoft 365 tenant; the governance extras need ==@Agent 365 or Microsoft 365 E7==. Treat the screenshots below as your lab.

## In one sentence

Agent management in the Microsoft 365 admin center (Agent 365) is the tenant-wide **registry** of every agent, where an AI Administrator reviews requests, publishes or rejects, scopes who gets each agent, blocks or deletes it, and fixes ownerless or risky agents.

## Why it exists

Departments build agents faster than IT can review them. Each one may read mailboxes or SharePoint, call external APIs, and keep running after its creator leaves. Think of an app store with a front desk: nothing reaches staff until the desk approves it, the desk decides which floors see it, and it can pull anything off the shelf instantly.

For a SOC analyst: when Defender flags a risky agent, this is the console where someone actually blocks it.

## What actually matters

1. **Registry.** **Agents > All agents > Registry** lists every agent by publisher type: **Microsoft agents**, **External partner-built**, **Published by your org** (LOB) and **Shared by creator**. The same Copilot Studio agent can appear twice (shared and published) — by design. Summary tiles: **Total agents**, **Agents without owners**, **Unmanaged agents** (outside Agent 365). Filters: Status, Publisher type, Channel, Platform, Data source. **Export to Excel** (all or filtered agents); a Graph API (needs Agent 365/E7).

2. **Requests and approval.** A published submission lands in **Requests**. Actions: **Publish** (to the Agent Store) or **Reject**. Until approved, even the maker can't use it in production Copilot. Review against least privilege, trusted publisher, clear purpose and AI policy. For agents that create instances, **Activate** scopes who may create them and applies a **policy template** (default: Entra, Purview, SharePoint, Defender controls).

3. **Scope and install.** Approval ≠ everyone. Limit users/groups (start with a pilot group). **Install** pre-deploys an agent and requires reviewing permissions and **Grant admin consent**. Copilot Studio agents use **on-behalf-of** auth — the user's own permissions are the ceiling.

4. **Block, delete, owners.**
   - **Block / Unblock:** org-wide, immediate, reversible — the right move during an investigation. For Agent Builder and Copilot Studio agents it blocks across Copilot, Teams and Outlook; for SharePoint or Foundry agents it only affects Copilot Chat.
   - **Delete:** soft delete, ==@30-day== restore window, then permanent (or permanently delete early).
   - **Ownerless agents:** shared agents become ownerless when the creator's account is deleted. Fix with **Assign new owner** (Agent Builder and Copilot Studio shared agents only), or block/delete.
   - **Start / Stop** for Foundry agents deallocates Azure compute. The Agent 365 doc says it needs **Azure AI Owner** — that role is now named ==@Foundry Owner== (same role ID, renamed).

5. **Risk.** The **Risks** column and **Agents at risk** tile aggregate signals from Entra, Defender and Purview (up to an hour behind those portals). Needs an **E7 or Agent 365** licence.

6. **Tenant settings.** **Agents > Settings**: **Agent and plugin access** (allow agents/plugins built by Microsoft, by your organization, by external publishers — a disabled Microsoft type still shows but can't be installed), **Sharing** (All users / No users / Specific users — ==!Agent Builder agents only==) and **Policy templates**.

7. **Roles.** ==@AI Administrator== (or Global Administrator) manages. ==@AI Reader== is the least-privilege inventory viewer. Global Reader, Security Administrator, Security Reader, Reports Reader and User Experience Success Manager can view but ==!not approve or assign owners==. Product admins (Power Platform Administrator, Fabric Administrator) govern only inside their own product.

### Licensing — product docs vs training

| Source | What it says |
|---|---|
| Product docs | Agent 365 is GA (May 1, 2026), licensed ==@per user== — agents don't need their own licence; they're covered by the licensed user who owns or manages them. At least one user needs a qualifying Agent 365 licence. Included in **Microsoft 365 E7** (E5 + Copilot + Entra Suite + Agent 365). The ==+registry and basic governance actions== (publish, deploy, block, delete, approve, scope, reassign owner) come with ordinary Microsoft 365 Enterprise/Business plans. ==@Policy templates, observability, tenant-wide tool control, the Graph API and risk signals need E7 or Agent 365.== |
| Training unit | "Requires a Microsoft 365 Copilot license"; Copilot customers "inherit Agent 365 capabilities automatically". |

> **Contradiction — product docs win.** Agent 365 is its own per-user licence (or part of E7), not something every Copilot tenant inherits.

## Where it lives

**Microsoft 365 admin center** (`admin.microsoft.com`) **> Agents > Overview** (dashboard, last 30 days) and **> All agents** (tabs **Registry**, **Requests**, **Deleted**). Select an agent to open its details pane: Install, Block, Delete, Assign new owner, Instances. Connector DLP lives in the **Power Platform admin center > Data policies**, not here.

## Exam traps

- **Wrong portal.** Agent registry and blocking = Microsoft 365 admin center. Agent *identity* access and Conditional Access = Entra admin center ([D3.1.4](D3.1.4.html), [D3.1.6](D3.1.6.html)). ==!AI Administrators can't configure Conditional Access.==
- **Block vs reject vs delete.** Reject = never published. Block = published but switched off, reversible. Delete = 30-day soft delete.
- **Security roles view only.** Security Administrator can't publish.
- **"Blocking an agent needs Agent 365."** ==!No== — block, delete, approve and reassign owner are basic registry actions in ordinary Microsoft 365 plans. ==+Policy templates and risk signals== are the Agent 365 part.
- **Foundry agent posture** (inventory, risk) now needs Agent 365 too (from July 1, 2026 — [D3.1.10](D3.1.10.html)).
- **Copilot Studio real-time protection** is a Defender setting ([D3.1.3](D3.1.3.html)), not an admin-center action.
