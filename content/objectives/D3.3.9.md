## Azure first

- **Azure API Management (APIM)** is a gateway in front of your APIs. Callers hit the **gateway**; APIM forwards to the **back end** (App Service, Functions, Logic Apps, AKS, Azure OpenAI...).
- **Products** group APIs; a **subscription** to a product (or API) gives the caller a **subscription key**.
- **Policies** are XML rules that run in four sections — `inbound`, `backend`, `outbound`, `on-error` — at four scopes: **global → product → API → operation**. `<base />` pulls in the parent scope's policies.
- **Tiers** decide network features: classic **Developer / Basic / Standard / Premium**, v2 **Basic v2 / Standard v2 / Premium v2**, and **Consumption**.

See the Foundations pages listed above, especially *api-management-basics* and *oauth-tokens-and-consent*.

## In one sentence

APIM protects back-end APIs in two directions: on the way in it checks who the caller is and how much they may call (subscription keys, `validate-azure-ad-token` / `validate-jwt`, client certificates, `ip-filter`, `rate-limit`, `quota`, VNet or private endpoint), and on the way out it proves itself to the back end (managed identity or client certificate) so the back end can refuse anyone who skipped the gateway.

## Why it exists

Your partner API is a public URL on a Function app. Anyone can call it, as often as they like, from anywhere. APIM is the reception desk of a secure building: check the badge (token), check the visitor list (subscription), wave through only listed addresses (IP filter), stop people who come in too often (rate limit), then escort the visitor to the office with a staff pass the office trusts (managed identity / certificate). The office door (back end) accepts only escorted visitors.

## What actually matters

**1. Subscription keys.** Primary + secondary key per subscription, sent in the `Ocp-Apim-Subscription-Key` header or `subscription-key` query string. Scope: **product**, **API** or **all APIs** (global). Rotate by handing out the secondary, then regenerating the primary. ==!A key is a shared secret, not an identity== — leaked keys work for anyone. Combine with token validation.

**2. Token validation.**

- `validate-azure-ad-token` — purpose-built for Microsoft Entra: `tenant-id`, allowed `client-application-ids`, audiences, required claims. ==+Prefer it for Entra tokens.==
- `validate-jwt` — any issuer: `openid-config` URL for signing keys, `required-claims` (for example `aud` = your API's app ID), `failed-validation-httpcode` (401). Use for non-Entra identity providers.
- Both run in **inbound**, before the back end is called. Put them at **product** or **API** scope, not global (health and documentation endpoints would break).

**3. Client certificates (inbound mTLS).** `validate-client-certificate` checks thumbprint or issuer/subject, plus `validate-revocation`, `validate-not-before`, `validate-not-after`.

**4. Abuse controls.**

| Policy | Counts | Over the limit |
|---|---|---|
| `rate-limit` | calls per subscription per short window (`calls`, `renewal-period` seconds) | ==@429== Too Many Requests |
| `rate-limit-by-key` | calls per custom key (IP, JWT claim, header) | 429 |
| `quota` | calls and/or bandwidth per subscription over a long period | ==@403== Forbidden |
| `quota-by-key` | same, per custom key | 403 |

`rate-limit` stops bursts; `quota` enforces contract volume. `ip-filter action="allow"` (or `deny`) with `<address>` / `<address-range>` — APIM sees the **proxy/NAT** IP if one sits in front.

**5. Back-end authentication.**

- ==+`authentication-managed-identity`== `resource="..."` gets an Entra token for APIM's system- or user-assigned identity (`client-id`) and sets the `Authorization: Bearer` header. The back end validates that token (for example Easy Auth on the Function app) and grants a role. You can configure the same on a **backend entity** instead of in policy.
- **Client certificate to back end** (`authentication-certificate`, or certificate on the backend entity): APIM presents a certificate; the back end accepts only it. Store certificates in **Key Vault** (APIM's managed identity needs read access) so renewals flow through.
- **Named values** backed by Key Vault hold secrets used in policies; never paste secrets into XML.
- Then **lock the back end** to APIM (access restriction to APIM's IP / VNet, or private endpoint), otherwise callers skip the gateway.
- ==!Anyone who can edit APIM policies can use the managed identity== (they can capture the token). Restrict *API Management Service Contributor* and policy-write rights; give the identity least privilege.

**6. Network models.**

| Model | Tiers | Inbound | Outbound to private back ends |
|---|---|---|---|
| VNet injection — **external** | Developer, Premium (classic) | Public endpoint | Yes |
| VNet injection — **internal** | Developer, Premium (classic) | ==+Private only== | Yes |
| VNet injection (v2) | Premium v2 | Private only | Yes |
| VNet **integration** | Standard v2, Premium v2 | ==!Still public== | Yes |
| Inbound **private endpoint** | Developer, Basic, Standard, Standard v2, Premium, Premium v2 | Private IP | No (inbound only) |

Front an internal APIM with **Application Gateway WAF** to inspect public traffic (D3.3.8).

**7. Defender for APIs.** Defender for Cloud plan for REST APIs **published in APIM** (not self-hosted gateways or workspaces). Two steps: enable the plan on the subscription, then onboard APIs (recommendation *Azure API Management APIs should be onboarded to Defender for APIs* > **Fix**). Gives inventory, findings for **unauthenticated**, **unused (30 days)** and **external** APIs, sensitive-data classification, and runtime alerts for OWASP API Top 10 threats. First insights about 30 minutes after onboarding. Attack paths need Defender CSPM.

**AI Gateway** (token limits, semantic caching, load balancing to Foundry models) is the same gateway pointed at AI back ends — that's D3.1.7.

## Where it lives

- **Azure portal > API Management services > *instance* > APIs > *API* > Design > Inbound processing > Policy code editor** (`</>`); **> Products** (product scope); **> APIs > All APIs** (global scope).
- **> Subscriptions** (keys); **> Security > Managed identities**; **> Security > Certificates**; **> APIs > Backends**; **> APIs > Named values**.
- **> Deployment + infrastructure > Network** (VNet mode, private endpoints).
- **> Security > Defender for Cloud** (API recommendations and alerts).

```xml
<inbound>
  <base />
  <ip-filter action="allow"><address-range from="203.0.113.0" to="203.0.113.255" /></ip-filter>
  <rate-limit calls="100" renewal-period="60" />
  <validate-azure-ad-token tenant-id="{tenant-id}">
    <client-application-ids><application-id>{partner-app-id}</application-id></client-application-ids>
  </validate-azure-ad-token>
  <authentication-managed-identity resource="api://{backend-app-id}" />
</inbound>
```

## Exam traps

- "Reject callers without a valid Entra token before the back end is hit" → ==+`validate-azure-ad-token`== (or `validate-jwt`) in **inbound**.
- "Partner key leaked" → regenerate that subscription's key; long-term add token validation.
- 429 vs 403 → rate-limit vs quota.
- "APIM must call a Function app without storing a secret" → ==+`authentication-managed-identity`== + Easy Auth on the Function; `authentication-basic` and named-value passwords are distractors.
- "Gateway reachable only from the corporate network" → internal VNet mode (Developer/Premium), Premium v2 injection, or private endpoint. ==!Standard v2 VNet integration leaves the gateway public.==
- `ip-filter` blocks everyone behind the partner's NAT → filter on the NAT egress IP.
- Policies at global scope break the developer portal health check → use product/API scope.
- "Find APIs with no authentication" → Defender for APIs.
