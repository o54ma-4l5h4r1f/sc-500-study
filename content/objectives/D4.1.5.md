## Azure first

- An **Azure VM** runs an operating system from a managed disk. Installed software on that disk is what a vulnerability scanner inventories and compares against known **CVEs** (published vulnerability IDs).
- **Defender for Servers** (Plan 1 or Plan 2) is the Defender for Cloud plan for machines. It deploys the **Microsoft Defender for Endpoint (MDE)** sensor as a VM extension.
- **Microsoft Defender Vulnerability Management (MDVM)** is Microsoft's vulnerability engine. Defender for Servers uses it as the built-in scanner — there is nothing extra to buy for core scanning.
- Findings show in two portals: **Azure portal** (Defender for Cloud recommendations) and **Defender portal** (`security.microsoft.com`, Exposure Management).

See the Foundations pages listed above. The plan-level switches are on **D3.2.6**; agentless snapshots on **D3.2.7**.

## In one sentence

MDVM settings decide which scanner feeds your VM vulnerability data, which result wins when two scanners report, what you do with findings (fix, export, suppress), and whether you get the Plan 2 premium tools on top.

## Why it exists

As an analyst you saw "CVE-2024-xxxx on VM-web01" and asked "is it patched yet?". Someone had to make sure every VM was scanned, by one consistent engine, and that accepted risks didn't flood the queue. That is this page.

Think of a car inspection. Plan 1 is the annual check (does every car have a valid certificate?). Plan 2 adds the extras: emissions benchmark, clamping a car that fails until it's fixed, checking the tyres' age.

## What actually matters

**1. Core vs premium MDVM.** Core MDVM comes with both Defender for Servers plans (the plan includes an MDE Plan 2 licence for servers). Premium needs **Plan 2**.

| MDVM capability | Plan 1 | Plan 2 |
|---|---|---|
| Agent-based scanning (MDE sensor) | ==+Yes== | Yes |
| Agentless scanning (disk snapshots) | ==!No== | Yes (also with Defender CSPM) |
| Software inventory, configuration assessment, risk-based prioritization, remediation tracking | Yes | Yes |
| **Security baselines assessment** (CIS, STIG) | No | ==@Yes== |
| **Block vulnerable applications** | No | ==@Yes== |
| Certificate, browser extension, network share and hardware/firmware assessments | No | Yes |

Premium features are configured and viewed in the **Defender portal** only.

**2. Choosing the scanner.** Servers plan > Settings > **Vulnerability assessment for machines** > **Edit configuration** > *Microsoft Defender Vulnerability Management*. It is on by default when the plan is enabled. When agentless scanning is also on: a machine with only one method shows that method's results; a machine with both shows ==@agent-based results only== (fresher). If a legacy partner (BYOL) scanner reports, Defender for Cloud shows the partner's results by default; manually enabling the MDVM setting on the subscription forces MDVM results instead.

> **Contradiction — product docs win.** The training units present Qualys/Rapid7 **BYOL** as a live alternative that needs no paid plan. BYOL is deprecated (no new onboarding from 3 February, data gone by 1 May, see D3.2.6). Microsoft now points third-party scanner data to **Exposure Management data connectors** (Tenable, Qualys, Rapid7), which "replace the bring your own license scanners".

**3. Close coverage gaps.** The recommendation ==@Machines should have a vulnerability assessment solution== lists VMs with no scanner. ==!Dated fact:== Microsoft announced (release notes, 23 Sep 2026) that this grouped recommendation is ==!deprecated on 14 December 2026== in favour of individual recommendations — expect either name in questions. Open it, select machines, deploy MDVM; they move to Healthy within 24 hours. Per VM by API: `PUT` (enable) or `DELETE` (disable) on `.../virtualMachines/{vm}/providers/Microsoft.Security/serverVulnerabilityAssessments/mdetvm`.

**4. Read the findings.** CVEs appear as Defender for Cloud recommendations (the training unit names the aggregate ==@Machines should have vulnerability findings resolved==; the product UI now groups them under **Vulnerabilities** as individual recommendations). Each shows CVEs, severity, CVSS score (0.0–10.0), patchability and remediation steps. The Defender portal shows them under **Exposure Management > Vulnerability management > Overview > Cloud**. Export at scale with **Azure Resource Graph** (`securityresources`, type `microsoft.security/assessments`; CVE details in the tenant-level `microsoft.security/cvedetails` type).

**5. Accepted risk: exemptions, not disable rules.** Disable rules filter findings by CVE, ID, category, CVSS threshold, minimum severity or patchable status, need permission to edit Azure Policy (**Resource Policy Contributor**), and take up to 24 hours. ==!Disable rules are being deprecated== with the move to individual recommendations; use **recommendation exemptions** instead (D1.3.3).

**6. Software inventory.** Defender for Cloud **Inventory** has an **Installed applications** filter and tab, backed by MDVM (agent) or agentless scanning. It needs ==@Defender CSPM or a Defender for Servers plan==. Query it in Resource Graph Explorer for "which VMs run OpenSSL x.y".

**7. Premium settings in the Defender portal.** **Baseline assessments** > Profiles > Create profile: OS, benchmark (**CIS** or **STIG**), compliance level, device groups; checks **Group Policy** settings only (not Intune). Time-limited **exceptions** cover known deviations. **Block vulnerable applications** needs Microsoft Defender Antivirus in **active** mode, cloud-delivered protection and **Allow or block file** turned on.

**Roles:** subscription-level scanning settings — Security Admin, Contributor or Owner; deploy the scanner — ==@Owner on the resource group==; view findings — **Security Reader**.

## Where it lives

- **Azure portal** > Defender for Cloud > Environment settings > *subscription* > Defender for Servers > Monitoring coverage **Settings** > Vulnerability assessment for machines > **Edit configuration**.
- **Azure portal** > Defender for Cloud > **Recommendations** > Vulnerabilities (findings) and *Machines should have a vulnerability assessment solution* (gaps); **Inventory** > Installed applications.
- **Defender portal** > Exposure Management > Vulnerability management > **Overview > Cloud** / **Vulnerabilities > Cloud** / **Baseline assessments**; Settings > Endpoints > Advanced features > Allow or block file.

## Exam traps

- "Which scanner for Azure VM vulnerability assessment, no extra licence?" → ==+MDVM== (built into Defender for Servers). Not Qualys, not BYOL.
- "VM has the MDE sensor and agentless scanning is on — which result shows?" → **agent-based**.
- "CIS benchmark compliance for Windows Server VMs" → MDVM **security baselines assessment** — ==!Plan 2 only==.
- "Prevent a vulnerable app version from running until patched" → **Block vulnerable applications** (Plan 2; Defender Antivirus active mode).
- "Suppress unpatchable low-severity findings going forward" → **exemption** (disable rules are being deprecated).
- "Find every VM running a given software version" → **software inventory** (Inventory or Resource Graph).
- "Plan 1 only, no agent on some VMs" → those VMs aren't scanned; agentless needs Plan 2 or Defender CSPM.

- **Skip:** the full disable-rule field list beyond "filter by CVE, severity, CVSS, patchable". The feature is on its way out.
