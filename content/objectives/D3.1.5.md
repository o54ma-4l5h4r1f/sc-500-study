## Azure first

- An **agent identity** (Entra Agent ID) is the account an AI agent signs in with. Whatever that account can reach, an attacker who controls the agent can reach.
- **Application permissions** (for example `Mail.ReadWrite.All`) let an identity act across the whole tenant with no user. **Delegated** permissions are capped by the signed-in user. See D1.1.5.
- **Knowledge sources** are the SharePoint sites, files or databases an agent reads to ground answers. **Tools** are actions it can take (send mail, write a record, run code).
- **Microsoft Security Exposure Management** is the Defender-portal area that draws the **attack surface map** (assets and how they connect) and computes **attack paths** to **critical assets** you mark as crown jewels.
- **Licence:** `license_blocked`. From ==@July 1, 2026== agent discovery, posture and threat detection need a ==@Microsoft Agent 365== licence, not Defender for Cloud Apps or Defender for Cloud alone. Portal tour only.

New to these? Read the Foundations pages listed in "Before you start".

## In one sentence

Blast radius is everything a compromised agent identity could read, change or send, and the Defender portal shows it through the **AI agents** inventory (risk level, indicators, recommendations), Advanced hunting, and Exposure Management attack paths.

## Why it exists

As an analyst, when a user account was phished you asked "what could this account touch?" before you scoped the incident. Agents need the same question asked *before* the incident. Agents are often granted broad rights "to make the demo work" and never trimmed. They also combine wide data access with actions, which human-facing apps rarely do.

Think of a set of master keys. A key to the post room is a small risk. A key that opens the post room, the HR cabinet and the courier van is a large one — even if nobody has stolen it yet. Blast radius is counting the doors each key opens.

## What actually matters

**1. Blast radius vs attack path.**

| | Blast radius | Attack path |
|---|---|---|
| Question | What can this identity reach if compromised? | How would an attacker get from an entry point to a critical asset? |
| Nature | static scope | dynamic chain of steps |
| Where | agent page (risk indicators, identities, tools), Advanced hunting | Exposure Management > Attack surface > Attack paths; **View blast radius** from a choke point |

There is a third entry point: in an **incident graph**, select a node > ==@View blast radius==. It draws the top eight attack paths from that node to critical targets (bounded at seven hops) — useful once an agent is already in an incident.

A **choke point** is a node where many attack paths meet. Fixing it cuts several paths at once. Prioritise by ==@what the path ends at==, not by how many steps it has.

**2. The AI agents inventory.** Defender portal **Assets > AI agents > Agents** tab. It lists Copilot Studio, Foundry, Microsoft 365 and supported non-Microsoft agents (via the Agent 365 registry), plus local agents found on endpoints. Columns include **Risk level**, **Risk indicators**, **Recommendations** and **Active alerts**. **Open Agent page** shows configuration, identity and authentication, attack-surface relationships, alerts, recommendations, tools and MCP servers.

**3. Risk level and indicators.** Defender combines active **risk indicators** into a level: ==@High, Medium, Low, No known risk, Not evaluated==. Example indicators: **Weak Instructions**, **High-usage Agent**, **Indirect Prompt Injection Exposure**, **Privileged Business-system Access**, **Active Threat**. Security **recommendations** are calculated ==!separately== — a high-risk agent can have none; a low-risk one can have some. Read both.

**4. Advanced hunting.** Query the inventory with ==@`AgentsInfo`== (it replaces `AIAgentsInfo`). The table keeps snapshots, so take the latest row per agent. Microsoft ships prebuilt queries under **Queries > AI Agents**.

```kusto
AgentsInfo
| summarize arg_max(Timestamp, *) by AgentId
| where LifecycleStatus != "Deleted"
```

**5. What makes the radius big.** Tenant-wide application permissions (`Mail.ReadWrite.All`, `Files.ReadWrite.All`, `Sites.FullControl.All`), several broad permissions together, knowledge sources holding labeled or restricted content (the agent can ==!bypass the site's own access model== for its users), and tools that move data out (send mail, external APIs). A dormant agent with broad rights is ==!as exploitable as an active one==.

**6. Shrinking it.** Remove unused permissions; swap broad for scoped ones (`Sites.FullControl.All` → `Sites.Selected`, `User.Read.All` → `User.ReadBasic.All`). Remove knowledge sources the agent doesn't need. Remove risky tools or add human approval. Apply Conditional Access for agents (D3.1.4). Agree changes with the agent's owner and sponsor first — you can break a production workflow.

## Where it lives

| Task | Path |
|---|---|
| Turn on security for AI agents | Defender portal > Settings > Security for AI > Get started (Security Administrator) |
| Agent inventory, agent page | Defender portal > Assets > AI agents |
| Hunting | Defender portal > Investigation & response > Hunting > Advanced hunting |
| Attack paths, choke points, blast radius | Defender portal > Exposure Management > Attack surface > Attack paths |

Attack paths are only as good as your data: mark **critical assets**, or the graph under-reports. In GCC, agent risk assessment, recommendations and the attack surface graph ==!aren't supported==.

## Exam traps

- **Blast radius = attack path.** ==!No.== Radius is reach; a path is the attacker's route to a critical asset.
- **Agent risk level comes from recommendations.** ==!No== — from active risk indicators; recommendations are separate.
- **Query `AIAgentsInfo`** → being deprecated; use ==+`AgentsInfo`==.
- **Agent missing from a real-time protection exclusion list or a CA picker** → it has ==!no Entra agent ID==; only agents with one can be targeted.
- **Licence after July 1, 2026** → ==+Agent 365==, not Defender for Cloud Apps.
- **"Blueprint configuration" in a question** may mean the agent's *actions* (module wording) — not the Entra **agent identity blueprint**. Read carefully.
- **Fewest changes to cut most paths** → fix the ==+choke point==.

> **Contradictions — training module vs product docs (product wins).** (1) The module says the Copilot Studio inventory supports discovery only and posture must be assessed through Advanced hunting; the current inventory doc shows a details pane and risk level for Copilot Studio agents. (2) The module opens attack paths from the agent pane with **View on map**; the product shows attack-surface relationships on the agent page and attack paths under Exposure Management. (3) The module says you opt in to preview features in Defender XDR and Defender for Cloud; the product says onboard to Agent 365, which turns security for AI agents on automatically. (4) The module's remediation suggests Conditional Access by network location or device compliance for agents; for agent identities CA supports only agent risk and Block (D3.1.4). The module labels the inventory **Preview**; the current doc has no banner, and the transition article still places this under the Agent 365 change.

## Skip

- **Skip:** the module's "34 vs 22 agents" story and "80% smaller blast radius" figure. Narrative numbers.
- **Skip:** local agent discovery prerequisites in Defender for Endpoint. Separate onboarding.
- **Skip:** on-premises attack path "End Game" assets (Domain Admins, domain controllers). Identity infrastructure, not agents.
- **Skip:** Foundry agent recommendations via Defender for Cloud connectors and third-party registry sync. Know they now flow through Agent 365.
- **Skip:** the full `AgentsInfo` schema. Know the table name and `arg_max`.
