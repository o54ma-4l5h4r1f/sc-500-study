## Azure first

- In Defender for Cloud a **security standard** (also called a framework) is a list of **controls**. Each control maps to one or more **recommendations** — the checks you already know. In Azure a standard is an **Azure Policy initiative** underneath.
- A **management group** sits above subscriptions; an **AWS management account** sits above AWS member accounts; a **GCP organization** sits above GCP projects. Assigning at the top covers everything below.
- The **Regulatory compliance** dashboard is the page that scores each assigned standard.

See the Foundations pages listed above, especially *defender-for-cloud-basics*.

> **Two pages, one module.** The mechanics — assigning a standard, the green/red/grey control states, manual attestation, Control details tabs, Download report, Audit reports, continuous export, roles — are taught on **D1.3.2**. This page is the posture angle: *which* framework fits which cloud and obligation, and how you read results across frameworks. Read D1.3.2 first.

## In one sentence

Evaluating compliance means choosing the frameworks that match your obligations and clouds, assigning them at the highest scope, and reading each framework's control results as a view of the same underlying recommendations.

## Why it exists

A bank must prove PCI DSS. A hospital must prove HIPAA. A European supplier now gets asked about DORA and NIS2. Each auditor brings a different chapter list, but they all ask about the same storage firewall and the same MFA setting. Defender for Cloud runs the checks once and re-sorts the results into each auditor's chapters. Think of one set of exam answers marked against three different mark schemes.

## What actually matters

**1. What you get by default, per cloud.**

| Environment | Assigned automatically |
|---|---|
| Azure subscription | ==@Microsoft cloud security benchmark (MCSB)== |
| AWS account | MCSB ==+plus== AWS Foundational Security Best Practices |
| GCP project | MCSB ==+plus== GCP Default |

MCSB v2 is in preview alongside the current MCSB. Foundational CSPM gives you MCSB only. Every other framework needs a paid plan (D1.3.2 has the exact rule).

**2. Pick frameworks by cloud — not every framework covers every cloud.** The built-in catalogue (product docs) includes:

| Framework | Azure | AWS | GCP |
|---|---|---|---|
| ISO/IEC 27001:2022, PCI DSS v4.0.1, NIST SP 800-53 R5.1.1, NIST CSF v2.0 | ✔ | ✔ | ✔ |
| CIS Controls v8.1, SOC 2023, HITRUST CSF v11.3.0, GDPR, NIS2, DORA, EU AI Act | ✔ | ✔ | ✔ |
| CIS Azure Foundations v2.1.0 (and v3.0) · CIS AKS Benchmark | ✔ | — | — |
| CIS AWS Foundations v3.0.0 · CIS EKS Benchmark · AWS Well Architected Framework 2024 | — | ✔ | — |
| CIS GCP Foundations v3.0 · CIS GKE Benchmark | — | — | ✔ |
| ==!HIPAA==, ==!FedRAMP 'H' & 'M'== | ✔ | ==!—== | ==!—== |
| SOC 2 | ✔ | — | ✔ |
| CCPA | — | ✔ | ✔ |

The pattern to remember: the **international and EU frameworks cover all three clouds**; each cloud has **its own CIS Foundations** benchmark; ==!HIPAA and FedRAMP are Azure-only== in this catalogue. The list changes, so check before you commit a programme to one.

**3. Assign at the highest scope that matches the framework.** Management group, AWS management account or GCP organization — results then roll up for everything below. A standard with ==!no relevant resources in scope doesn't appear on the dashboard==. First results take up to 12 hours; Azure assessments rerun about every 12 hours. For new AWS and GCP connectors, compliance data refreshes on a 4-hour minimum, so allow 12–24 hours for stable numbers (training module figure).

**4. Your own framework = a custom standard.** When an internal baseline doesn't match any built-in framework, create a **custom standard** and fill it with built-in and custom recommendations. **KQL custom recommendations** work across Azure, AWS and GCP and ==!need Defender CSPM==; Azure Policy-based custom recommendations (now labelled **legacy**, Azure only) are available to everyone. Creating a standard needs **Owner**; creating a custom recommendation needs **Security Admin**. The build steps are on D1.3.3.

> **Contradiction — product docs win.** Unit 2 says "creating and managing custom standards requires Defender CSPM". The product article says only **KQL-based** custom recommendations need Defender CSPM; Azure Policy-based ones are available to all customers.

**5. Read across frameworks, not one at a time.** The dashboard lists the **lowest-performing standards** first. Filter **Recommendations** by a framework to plan a sprint against one audit. Because many recommendations feed several frameworks, the fix list for PCI DSS overlaps heavily with ISO 27001. For trend, use the **Compliance over time** workbook; for a point-in-time auditor pack, **Download report** (PDF or CSV). Assigned standards also flow into **Microsoft Purview Compliance Manager** with no extra setup.

## Where it lives

- **Configure (Azure portal):** Microsoft Defender for Cloud > Regulatory compliance > **Manage compliance policies** > *management group / subscription / AWS account / GCP project* > Security policies > toggle the standard **On**.
- **Monitor (Defender portal):** Cloud security > **Regulatory compliance** (read-only) and Exposure Management > Recommendations > filter by standard.
- **Custom standard:** Azure portal > Defender for Cloud > Environment settings > *scope* > Security policies > **+ Create > Standard**.

![Turn a standard on](https://learn.microsoft.com/en-us/azure/defender-for-cloud/media/update-regulatory-compliance-packages/turn-standard-on.png){Security policies: toggle the framework On at the chosen scope}

## Exam traps

- "Assess AWS accounts against CIS" → **CIS AWS Foundations**, assigned on the AWS connector (management account for all members). ==!Not CIS Azure Foundations.==
- "Assess GCP projects against HIPAA" → not in the built-in catalogue for GCP; use a **custom standard**.
- "No action, but AWS findings already show a compliance score" → **AWS Foundational Security Best Practices** is auto-assigned with MCSB.
- "Track improvement over six months" → **Compliance over time** workbook, not Download report.
- "Org-specific baseline across all three clouds" → custom standard with **KQL** custom recommendations (Defender CSPM).
- ==!"Each framework runs its own scan."== They all read the same recommendations.

## Skip

- **Skip:** everything already on D1.3.2 — control states, attestation steps, Control details tabs, report formats, Audit reports, continuous export, the role table. Don't study it twice.
- **Skip:** unit 2's three-category essay (benchmark vs regulatory vs custom). One line: MCSB is the baseline; the rest you add.
- **Skip:** the long tail of regional frameworks (NZISM, RMIT Malaysia, Spanish ENS, k-ISMS-P, APRA CPS 234, Canada PBMM). Know the famous ones and the cloud-coverage pattern.
- **Skip:** unit 4's "up to seven days" for Compliance Manager to populate. It's a training-module figure, not a product limit.
- **Skip:** the KQL query editor and template catalogue for custom recommendations — D1.3.3.
