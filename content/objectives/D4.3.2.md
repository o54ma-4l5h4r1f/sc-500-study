## Azure first

Three different permission systems meet in Security Copilot. Keep them apart:

- **Microsoft Entra roles** (Global Administrator, Security Administrator, Security Operator…) are tenant-wide admin roles managed in the Entra admin center.
- **Azure RBAC roles** (Owner, Contributor, Microsoft Sentinel Reader…) grant access to Azure resources — here, the SCU **capacity resource** and any **Sentinel workspace**.
- **Security Copilot roles** (Copilot owner, Copilot contributor) exist *only inside Security Copilot*. They are assigned per workspace.
- A **role-assignable group** is an Entra security group that is allowed to hold role assignments.

See the Foundations pages listed above: Entra ID basics and Azure RBAC vs Entra roles.

## In one sentence

Security Copilot has just two roles of its own — **Copilot owner** (configures the workspace) and **Copilot contributor** (uses it) — and neither one grants any security data: what a prompt can actually read still depends on your Entra, Azure and product roles.

## What's new for an engineer

As an analyst you had "access to Copilot". Now you decide who gets it, per workspace, and you must explain why an analyst who *can* open Copilot still gets empty answers from the Sentinel plugin.

## What actually matters

- **Copilot roles are not Entra roles.** They "function like access groups", live in Security Copilot, and give **no access by themselves to security data**.
- **Inherited owners.** These Entra roles automatically inherit Copilot owner: **Billing Administrator, Entra Compliance Administrator, Global Administrator, Intune Administrator, Security Administrator**. These Purview roles do too: **Purview Compliance Administrator, Purview Data Governance Administrator, Purview Organization Management**. On an auto-provisioned (E5/E7) tenant the default owner list also includes **Conditional Access Administrator** and ComplianceBundle.
- **Two owners always.** Security Copilot keeps at least two owners at all times; those two cannot be removed.
- **Contributors — three choices.**

| Contributor assignment | Good | Bad |
|---|---|---|
| ==@Recommended Microsoft Security roles== (default for new instances) | Gives Copilot to people who already hold security roles | All or nothing — one unwanted role means removing the whole group |
| Everyone | Legacy default, simple | Users without security data get a confusing experience; ==!once removed, it cannot be re-added== |
| Custom users / groups | Full control | More admin work |

- **Who can assign.** Only Global Administrator, Security Administrator or Copilot owner can add or remove owners and contributors. Assign to users, **role-assignable groups**, Entra roles or managed identities. New members can take **up to 5 minutes** to see the workspace.
- **Roles are per workspace.** Owner of the SOC workspace is *not* owner of the compliance workspace.
- **On-behalf-of (OBO).** Microsoft plugins act *as the signed-in user*. A contributor needs **Microsoft Sentinel Reader** (Azure RBAC) to see Sentinel incidents, an Intune role such as Endpoint Security Manager for Intune data, and Defender XDR unified RBAC for Defender data. Copilot never goes beyond your own access.
- **Capacity is separate again.** Creating or resizing SCUs needs **Azure Owner or Contributor** on the capacity resource (plus Copilot owner when done from the Copilot portal). Provisioning also needs Security Administrator or higher in the tenant.
- **Least privilege.** Do not hand out Security Administrator (a privileged role) just for Copilot access. Put users in a security group and add the group as owner or contributor.

| Capability | Owner | Contributor |
|---|---|---|
| Create sessions, run promptbooks | Yes | Yes |
| Manage personal custom plugins | Yes | Default No |
| Allow contributors to add / publish custom plugins | Yes | No |
| Restrict preinstalled plugins | Yes | No |
| Upload files | Yes | Default Yes |
| Data sharing settings, usage dashboard, capacity | Yes | No |

## Where it lives

- **Security Copilot portal** > home menu > **Owner > Role assignment > Add members** (or *Add role assignment*) > pick Owner or Contributor > user / group / role > **Add**. The **Owner** menu appears only if you are a Copilot owner.
- Entra role membership itself is managed only in the **Microsoft Entra admin center**.
- Azure roles on the capacity resource: **Azure portal > the capacity resource's resource group > Access control (IAM)**.
- Multitenant/MSSP access: B2B guest with **tenant switching**, GDAP (Partner Center) or Azure Lighthouse.

## Exam traps

- ==!"Assign Copilot contributor so the analyst can query Sentinel incidents"== — not enough. ==+Also assign Microsoft Sentinel Reader== on the workspace.
- ==!"Copilot owner is an Entra role"== — false. It is a Security Copilot role.
- Security Operator is **not** in the inherited-owner list.
- Viewing a **shared session** needs only Copilot contributor; the viewer does not need the plugin's underlying data access. Sessions are read-only and same-tenant only.
- A Global Administrator is a Copilot owner, but **not** automatically an Azure Owner of the capacity.
