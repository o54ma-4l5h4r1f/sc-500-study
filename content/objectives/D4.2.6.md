## Azure first

- A **Log Analytics workspace** is the database Sentinel reads.
- The **Azure Monitor Agent (AMA)** is the shipping program on each Windows machine. It runs on Azure VMs, or on non-Azure servers once they are connected through **Azure Arc**.
- A **data collection rule (DCR)** is an Azure resource: "collect these events from these machines, send them to that workspace". It filters **at the source**, so dropped events never leave the machine and are never billed.
- **Windows Event Forwarding (WEF)** is a feature built into Windows: many machines push events to one **Windows Event Collector (WEC)** server, with no extra agent on the sources.

See the Foundations pages listed above: Azure Monitor Agent and DCRs, Log Analytics workspace, Azure Arc, and VMs.

## In one sentence

The **Windows Security Events via AMA** connector builds a DCR that streams the Security (and AppLocker) events you choose — All, Common, Minimal or Custom XPath — into `SecurityEvent`; the **Windows Forwarded Events** connector puts AMA on a WEC server instead, and everything it forwards lands in `WindowsEvent`.

## What's new for an engineer

As an analyst you queried `SecurityEvent` for 4625 bursts. As the engineer you decide **which events exist to query**, and what that costs:

- **Pick the event set** per DCR. A domain controller on "All" can dominate the bill; "Minimal" may miss what a detection needs.
- **Arc first.** A physical or other-cloud server must be Arc-enabled **before** you enable the connector, or it never appears on the **Resources** tab.
- **Choose the architecture.** AMA on every machine (DCR per group) or WEF to a collector with AMA on the collector only. The second changes the table, and that breaks content.
- **Permissions:** read and write on the Sentinel workspace, plus rights to create DCRs (**Monitoring Contributor**) and push the agent (**Virtual Machine Contributor** / **Azure Connected Machine Resource Administrator**).

## What actually matters

| Event set | Contains | Pick it for |
|---|---|---|
| **All Security Events** | Every Security log and AppLocker event — ==!not== Application, System or Setup | Maximum visibility, highest cost |
| **Common** | Full user audit trail: logon and logoff (4624, 4634), group changes, DC Kerberos events | Auditing, compliance |
| **Minimal** | Breach indicators only: 4624, 4625, 4688, 1102… ==!no 4634 logoff== | Detection at low volume |
| **Custom** | Your XPath queries; can also pull other logs | Exact control |

1. **XPath rules.** Format `LogName!XPathQuery`, for example `Security!*[System[(EventID=4624 or EventID=4625)]]`. Up to **20 expressions per box, 100 boxes per rule**, **XPath 1.0 only** (`contains` and `starts-with` don't work). Test first with `Get-WinEvent -FilterXPath`.
2. **DCR location is flexible.** The DCR's subscription and resource group need not match the machines — same **tenant** is enough. AMA installs automatically on selected machines that lack it.
3. **Wrong-table trap.** A plain Azure Monitor DCR collecting the Security log writes to `Event`, not `SecurityEvent`. Sentinel's Windows content reads `SecurityEvent`. Use the Sentinel connector.
4. **Legacy agent.** The Log Analytics agent (MMA) was deprecated **31 August 2024**. Running both agents on one source doubles ingestion. The **AMA migration tracker** workbook shows who is still on MMA.
5. **Transformations** (a KQL query on the virtual table `source`) can filter what XPath can't. XPath at the agent is cheaper.
6. **Scale.** AMA on Windows targets about **5,000 events per second**.

**WEF and the Windows Forwarded Events connector**

| Piece | Role |
|---|---|
| Event source | Any Windows machine; built-in forwarding client, no AMA |
| **WEC** server | Receives events into its **ForwardedEvents** log; runs AMA |
| Subscription | On the WEC: which events (XPath), from whom |
| Connector | **Windows Forwarded Events** → `WindowsEvent` |

- **Source-initiated** subscriptions (sources pointed at the WEC by Group Policy **SubscriptionManager**) scale best; **collector-initiated** lists every source by name.
- Forwarded Security events go to ==@`WindowsEvent`==, never `SecurityEvent`. Built-in rules that query `SecurityEvent` won't fire; adapt them or use **ASIM** parsers (Microsoft recommends installing them).
- WEF is passive: it ==!can't turn on audit policy==. To forward the Security log, add **NETWORK SERVICE** to **Event Log Readers** on sources.
- A stable WEC handles about **3,000 events per second**.

## Where it lives

**Defender portal:** **Microsoft Sentinel > Content management > Content hub** → **Windows Security Events** (or **Windows Forwarded Events**). Then **Microsoft Sentinel > Configuration > Data connectors** > **Windows Security Events via AMA** (or **Windows Forwarded Events**) > **Open connector page** > **+Add data collection rule** → **Basics** → **Resources** → **Collect** → **Review + create**. Existing DCRs, including API-created ones, are listed under **Configuration** on the same page.

```powershell
Get-WinEvent -LogName 'Security' -FilterXPath '*[System[EventID=4624]]'   # test XPath
wecutil qc /q                                                              # on the WEC
```

```kql
WindowsEvent
| where Channel == "Security" and EventID == 4625
| project TimeGenerated, Computer, EventData
```

## Exam traps

- "Only successful and failed logons from DCs." ==+Custom XPath==, not ==!Minimal== (Minimal also brings 4688).
- "Full audit trail with sign-outs, lowest volume." ==+Common.== ==!Minimal has no 4634.==
- "All Security Events includes System." ==!False.==
- "DCR must sit in the machines' resource group." ==!False== — same tenant.
- "WEF Security events appear in `SecurityEvent`." ==!False== → ==+`WindowsEvent`==.
- "Install AMA on every WEF source." ==!No== — ==+only on the WEC==.
- "On-prem server missing from Resources." ==+Arc first.==

## Skip

- **Skip** *Connect using the Security Events via Legacy Agent Connector* (unit 4 of *Connect Windows hosts to Microsoft Sentinel*): the agent is deprecated.
- **Skip** *Collect Sysmon event logs* (unit 5): Sysmon is not on this bullet.
