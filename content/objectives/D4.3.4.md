## Azure first

- An **agent** is a Security Copilot automation that runs on a **trigger** (a schedule or an event, such as "new user-reported phish"), calls **plugins**, and writes results — without a person typing prompts.
- Every agent needs an **identity** to run as. The preferred kind is a **Microsoft Entra Agent ID**: a non-human identity made only for AI agents, like a service account with its own audit trail.
- The **Security Store** is Microsoft's security storefront for buying partner (and Microsoft) agents and solutions, billed through your Azure subscription.
- Agents consume **SCUs** from the workspace they run in.

See the Foundations pages listed above: AI agents and MCP basics, Entra ID basics, the Defender portal tour and RBAC vs Entra roles.

## In one sentence

You switch on Microsoft-built agents (and buy partner agents from the Security Store), give each one an identity, trigger and permissions inside a chosen workspace, and then run, pause, edit and tune them with feedback.

## What's new for an engineer

As an analyst you read the Phishing Triage Agent's verdicts. The engineer *set it up*: chose its identity, granted its permissions, met its prerequisites, decided which workspace pays for it and, for partner agents, got a Global Administrator to approve.

## What actually matters

- **Two sources of agents.** **Microsoft-built** agents (in the agent library and inside the Defender, Entra, Intune and Purview portals) and **partner-built** agents (bought through the Security Store). Examples to recognise:

| Portal | Microsoft-built agent | Notes |
|---|---|---|
| Defender | ==@Phishing Triage Agent== / Security Alert Triage Agent | Classifies user-reported phish (needs Defender for Office 365 Plan 2, unified RBAC). The broader Security Alert Triage version is preview |
| Defender | Threat Intelligence Briefing Agent, Threat Hunting Assistant, Security Analyst Agent, Dynamic Threat Detection Agent | Dynamic Threat Detection is preview, always on, no setup |
| Entra | ==@Conditional Access Optimization Agent== | Runs every 24 h; Security Administrator configures, Conditional Access Administrator uses; needs Entra ID P1 |
| Intune | Vulnerability Remediation Agent (preview), Change Review, Device Offboarding, Policy Configuration | Vulnerability Remediation uses Defender Vulnerability Management data |
| Purview | Data Security Triage Agent (DLP triage agent, Insider Risk Management triage agent) | Prioritizes the riskiest alerts; triages files up to 2 MB |

- **Setup parameters** (every agent): **Trigger, Permissions, Identity, Plugins, Products, Role-based access**.
- **Identity choice.** ==+Create an agent identity== (Entra Agent ID — recommended, better audit, smaller blast radius; currently Microsoft-built agents only) or **connect an existing user account** (the agent inherits that user's rights). A user-account identity does not work with PIM-activated roles or a Temporary Access Pass, because the agent runs long-term in the background.
- **Workspace context.** An agent runs in the workspace you were signed in to when you set it up. It uses that workspace's SCUs and plugins. Embedded agents follow the tenant-wide **Workspaces for Microsoft Security Copilot agents** routing.
- **Moving an agent** to another workspace: turn off its triggers first, then set it up again there. ==!Feedback and memory do not move.==
- **Partner agents and Global Administrator approval.** If a partner agent needs data from a Microsoft product (Defender, Sentinel, Intune, Entra, Defender Threat Intelligence), the **Set up** button stays disabled until a **Global Administrator** approves. The owner or contributor copies a link and sends it. Use PIM for just-in-time Global Administrator. Agents that need no Microsoft-product permissions need no approval.
- **Two separate bills.** Security Store subscription (the partner's licence fee) and SCU consumption (each run). ==!Removing an agent from Security Copilot does not cancel the Security Store subscription.==
- **Store purchase prerequisites.** Azure Contributor or Owner on the billing subscription; Copilot owner or contributor to set the agent up; possibly Global Administrator for permissions.
- **Dependent plugins.** After setup a partner agent's plugin may show "enabled" but not configured — finish it in **Manage sources** (for example, an API key).
- **Operate.** Run on trigger or **One time**; **Pause**; **Edit** (applies to later runs only); feedback **for the agent** is stored in its memory, feedback **to Microsoft** is not; **Manage memory > Reject feedback** removes an entry.

## Where it lives

| Task | Where |
|---|---|
| Agent library, set up Microsoft agents | Security Copilot portal > **Agents** > agent > **Set up** |
| Security Store | Security Copilot > home menu > **Security Store**, or Agents > **Browse more agents**; or `securitystore.microsoft.com` |
| Approve a partner agent | Global Administrator opens the shared link, or **Active agents** > **Set up** > **Start approval** |
| Embedded agents | Defender portal, **Microsoft Entra admin center > Agents**, **Intune admin center > Agents**, Purview portal |
| Agent routing per product | Security Copilot > **Owner settings > Workspaces for Microsoft Security Copilot agents** |
| Memory | Agent page > **…** > **Manage memory** |

## Exam traps

- ==!"Any Security Copilot owner can approve a partner agent's access to Defender data"== — no, ==+a Global Administrator approves==.
- ==!"Delete the agent to stop paying the partner"== — the Store subscription is billed separately.
- Agent identity (Entra Agent ID) is the **recommended** option, not the user account.
- An agent's plugin auto-enablement does not change plugin availability for users.
- E5/E7 inclusion covers SCUs for agents (including partner agents "until further notice"), but **not** partner licence fees bought in the Store.

## Skip

- **Skip:** each agent's detailed verdict logic, triage categories and reasoning maps. That is analyst usage.
- **Skip:** building custom agents (Agent Builder, YAML, MCP tools). Developer material beyond this bullet.
- **Skip:** the list of named partner agents (glueckkanja, adaQuest, Invoke…). The catalog changes constantly; know the Store mechanics instead.
- **Skip:** every product prerequisite row per agent. Remember the pattern: product licence + plugin + role + identity.
