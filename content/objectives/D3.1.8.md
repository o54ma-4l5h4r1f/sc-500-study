## Azure first

- **Microsoft Defender for Cloud** has a free posture layer and paid **plans**. **CWP (Cloud Workload Protection)** plans watch one workload type at runtime and raise alerts: Servers, Storage, Databases, Containers — and **AI services**.
- You switch plans on in **Environment settings**, per **Azure subscription**.
- A **Foundry resource** (formerly Azure AI services / Azure OpenAI) hosts **model deployments**. Apps send **prompts** (input) and receive **completions** (output) made of text **tokens**.
- **Azure AI Content Safety Prompt Shields** is Microsoft's classifier for prompt-injection attacks. **Microsoft Defender XDR** is the Defender portal where alerts from every Defender product become incidents.

See the Foundations pages listed above: Defender for Cloud basics, Foundry basics, Defender portal tour, Purview basics.

## In one sentence

Defender for AI Services is the Defender for Cloud CWP plan (portal label **AI services**) that scans the text going into and out of your Foundry/Azure OpenAI model deployments and raises security alerts — jailbreak, data leakage, credential theft, phishing URLs, wallet attacks — into Defender for Cloud and Defender XDR.

## Why it exists

As an analyst you triaged "A Jailbreak attempt on an Azure AI model deployment was blocked by Prompt Shields." That alert only exists because someone turned this plan on.

Think of a smoke detector wired to the fire brigade. Foundry guardrails ([D3.1.9](D3.1.9.html)) are the sprinkler: they block the bad prompt in place. Defender for AI Services is the alarm line to the SOC: it tells security that someone tried, correlates it with the same user's sign-ins and endpoints, and keeps evidence.

Without it, a blocked jailbreak is invisible to the SOC. It's just an error code in an app log.

## What actually matters

1. **What it detects.** Product docs list data leakage, data poisoning, jailbreak, credential theft "and more". The alert reference adds: jailbreak attempts **blocked** vs **detected** by Prompt Shields, credential theft in model responses, **ASCII smuggling** (invisible instructions — indirect prompt injection), phishing URLs in prompts or responses, access from Tor or suspicious IPs, suspicious user agents, access anomalies, **wallet attacks** (cost-exhaustion by repeated or high-volume requests), anomalous tool invocation, and LLM reconnaissance (preview).

2. **Scope and state.** ==@Generally available.== Covers Azure OpenAI supported models and Azure AI Model Inference supported models. ==!Text tokens only== — image and audio aren't scanned. Commercial Azure only: no Azure Government, no 21Vianet, ==!no connected AWS accounts==. Copilot Studio agents are protected separately, in the Defender portal under Security for AI ([D3.1.3](D3.1.3.html)). ==!Foundry *agent* alerts are leaving this plan:== from ==@July 1, 2026== agent-level threat detection for Foundry agents needs a ==@Microsoft Agent 365== licence and runs over Agent 365 observability logs. The plan keeps protecting ==+Foundry Models such as Azure OpenAI==.

3. **Enable per subscription.** **Environment settings > *subscription* > Defender plans > AI services > On > Save.** Needs **Owner** or **Contributor** on the subscription. A subscription without the plan has ==!no AI threat detection==, even if Servers or Storage plans are on. A resource-level setting also exists in ARM: `Microsoft.CognitiveServices/accounts/defenderForAISettings` with `state` `Enabled`/`Disabled`. Turning a plan off at subscription level doesn't stop a resource-level enablement.

4. **User prompt evidence.** Off: detection still runs, but prompt and response text is ==@masked== in alerts. On (**Settings > Enable user prompt evidence**): alerts carry the suspicious segment of the prompt or model response, with sensitive data auto-redacted. It shows in the Azure portal, the Defender portal and partner integrations. Turn it on when your data-handling policy allows analysts to see prompt text.

5. **The other two components.**
   - **Data security for AI interactions** (preview): lets **Microsoft Purview** analyse prompts and responses (SIT classification, DSPM for AI, Insider Risk, Communication Compliance, Audit, eDiscovery). ==!Paid Purview feature, not in the plan.== Doesn't cover Foundry **agents**. Full policy coverage needs Entra ID user-context tokens. The method is being moved into the Foundry portal (**Operate > Compliance**) — cross-link [D3.1.2](D3.1.2.html).
   - **AI model security** (preview): scans models in **Azure Machine Learning registries/workspaces** for malware, unsafe operators and exposed secrets. Needs Defender CSPM too. Scans weekly, 10 GB file limit.

6. **Cost and trial.** Billing is based on tokens scanned. A **30-day free trial capped at 75 billion tokens**; billing starts early if the cap is hit. Prices live on the reference page, not here.

### Alerts you should recognise

| Alert (abridged) | Type | Severity |
|---|---|---|
| Jailbreak attempt **blocked** by Prompt Shields | `AI.Azure_Jailbreak.ContentFiltering.BlockedAttempt` | Medium |
| Jailbreak attempt **detected** (not blocked) by Prompt Shields | `AI.Azure_Jailbreak.ContentFiltering.DetectedAttempt` | Medium |
| Credential theft attempts on a model deployment | `AI.Azure_CredentialTheftAttempt` | Medium |
| ASCII smuggling prompt injection | `AI.Azure_ASCIISmuggling` | High |
| Phishing URL in user prompt / model response | `AI.Azure_MaliciousUrl.*` | High |
| Access from a Tor IP / suspicious IP | `AI.Azure_AccessFromAnonymizedIP` / `...SuspiciousIP` | High |
| Suspected wallet attack (recurring requests / volume anomaly) | `AI.Azure_DOW*` | Medium |
| Anomalous tool invocation | `AI.Azure_AnomalousToolInvocation` | Low |

"Detected but not blocked" means the Foundry guardrail was set to annotate, or detection confidence was low. Fix the guardrail, not the plan.

## Where it lives

- **Azure portal > Microsoft Defender for Cloud > Management > Environment settings > *subscription* > Defender plans > AI services**. **Settings** on that row opens the three component toggles.
- **Alerts in Defender for Cloud:** **General > Security alerts > Add filter > Product Component Name = AI, AIServices**.
- **Alerts in Defender XDR:** `security.microsoft.com` > **Investigation & response > Incidents & alerts > Incidents**, filter **Service/detection source = Microsoft Defender for Cloud > Microsoft Defender for AI Services**. Prompt text is in the alert under **Activities > Related activities > Prompt Suspicious Segment**.

## Exam traps

- ==!Prompt evidence does not turn detection on or off.== Without it, alerts still fire; only the text is masked.
- ==!Data security for AI interactions is not included in the Defender plan== — it needs a separate Purview licence, and it doesn't capture Foundry agent interactions.
- **Subscription scope.** "We enabled Defender for Servers, why no jailbreak alerts?" → the AI services plan is off on that subscription.
- **Guardrail vs Defender.** Blocking a prompt = Foundry guardrail / Prompt Shields. Alerting the SOC and correlating into incidents = Defender for AI Services. The exam pairs them; they don't replace each other.
- **Copilot Studio agents ≠ this plan.** Their runtime protection is Security for AI in the Defender portal, licensed through ==+Agent 365== from July 1, 2026 (it used to be Defender for Cloud Apps).
- **"Enable Defender for AI Services to get Foundry agent threat detection."** ==!Not after July 1, 2026== — agent-level detection needs ==+Agent 365==; the plan covers model deployments.
- **AWS Bedrock** threats aren't covered by this plan (posture discovery of Bedrock is Defender CSPM — [D3.1.10](D3.1.10.html)).
- **Role to enable:** the enablement article says ==@Owner or Contributor== on the subscription; the overview says Owner, or a role with the matching data actions. A reader role can't switch plans on.

## Skip

- **Unit 4 of the protect-workloads module walks Manage incident fields** (severity, classification, tags). That's analyst work you already do.
- **The Take action menu, automation rules and Logic App playbooks** in the alert view: same as every other Defender alert.
- **Generic CWP signals in unit 5** (VM code injection, container privilege escalation). Those belong to Defender for Servers and Containers, not this plan.
- **The Purview troubleshooting PowerShell** (`New-AzADServicePrincipal` for the Purview app ID). Too operational.
- **AI model security file formats** (Pickle, ONNX, GGUF…). Know it scans Azure ML registries; skip the list.
- **Gaining end-user context for AI API calls** (passing user headers). Developer detail.
