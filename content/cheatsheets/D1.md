## D1.1 Entra ID access

Pages: [1.1.1](../objective/D1.1.1.html) PIM · [1.1.2](../objective/D1.1.2.html) CA · [1.1.3](../objective/D1.1.3.html) methods · [1.1.4](../objective/D1.1.4.html) apps · [1.1.5](../objective/D1.1.5.html) consent · [1.1.6](../objective/D1.1.6.html) managed identities

| PIM | Fact |
|---|---|
| Assignment axes | ==@Eligible== (no permission until activated) vs ==@Active==; permanent vs time-bound |
| Activation max | ==@1–24 h==, default 8 |
| Role settings | MFA or CA **authentication context**, justification, ticket (==!not validated==), approval (approver needs no admin role; none named → PRA/GA approve) |
| Surfaces | Entra roles (tenant, per role) · Azure resources (==@per role per scope==) · PIM for Groups (member/owner) |
| Groups | ==!Not dynamic or on-prem-synced==; role-assignable only if the group holds an Entra role |
| Licence | P2 or ID Governance. Expiry → ==!eligible Entra assignments removed==, permanent stay |
| Workloads | MI/SP ==!can't activate== → permanent, narrow RBAC |
| Access reviews | Auto apply + ==+If reviewers don't respond = Remove access==; recommendations = no sign-in 30 days |

| Conditional Access | Fact |
|---|---|
| Evaluation | ==!No priority order==. All matching policies apply; ==+any block wins== |
| When | After first factor, at token issue — group adds apply at token refresh |
| Role targeting | Built-in directory roles only |
| Workload identities | Single-tenant SPs, ==@Block only== (location, SP risk), Workload Identities Premium. ==!Not managed identities, not multitenant/SaaS apps==; assign SP directly, not via group |
| Agents (preview) | Agent 365 + P1/M365 E3, or M365 E7. "All users" excludes agent users |
| Can't combine | Require MFA + Require authentication strength |
| Report-only | ==!Never prompts or blocks==; can't test User actions |
| What If | Needs identity, resource, platform, client app; ignores service dependencies |
| Targets | Azure management = ==+Windows Azure Service Management API==; registration = user action ==+Register security information== |
| Licence | P1; risk conditions P2. Security defaults = free, no exclusions. P1 expiry → policies stay (view/delete only) |

**Methods (D1.1.3).** Which = **Authentication methods policy** · When = CA (or security defaults; per-user MFA ==!legacy==) · How strong = **authentication strength**.

- Phishing-resistant = ==+WHfB, FIDO2/passkeys, multifactor CBA, Platform Credential for macOS==. ==!Authenticator push/TOTP is not.== Push always uses number matching.
- Legacy MFA/SSPR policies can't manage methods since **30 Sep 2025**. States: Pre-migration → Migration in Progress → ==@Migration Complete==. Before Complete, a method enabled in any policy is usable.
- **TAP**: default 1 h, max 8 h, one-time off, length 8 (8–48), range 10 min–30 days.
- Trusted IPs ==!no IPv6== → named locations. MFA registration policy needs P2.

| App registration | Enterprise application |
|---|---|
| Application object, one per app, home tenant | Service principal, one per tenant using it |
| Credentials, redirect URIs, *requested* permissions | *Granted* consents, assignments, sign-in settings, logs |
| Application (client) ID — same everywhere | Object ID differs per tenant; ==+CA workload policies use this== |

- Credentials: ==+federated== > ==+certificate== > ==!client secret== (max 24 months, recommend under 12, shown once).
- **Enabled for users to sign-in = No** → no tokens, even app-permission ones. **Assignment required = Yes** → only assigned principals; ==!blocks user consent==. **Visible to users = No** only hides.
- Managed identity = SP with ==!no app object== (not under App registrations). Graph-created app has no SP until created.

| Consent | Delegated | Application |
|---|---|---|
| Acts as | Signed-in user (never more than the user) | App alone |
| Who consents | Users within policy; admins | ==!Admins only== |
| Record | `OAuth2PermissionGrant` | `appRoleAssignment` |

User consent options: Do not allow · verified publishers + low-impact (`microsoft-user-default-low`) · ==+Let Microsoft manage== (default, `…-recommended`) · ==!Allow for apps== (`…-legacy`). Changes affect ==!future consent only==. Admin consent workflow reviewers ==!get no rights==. User-consented grants revoke via ==@Graph/PowerShell only==.

**Managed identities (D1.1.6).** System-assigned dies with the resource; user-assigned is its own resource, shareable, ==!deleted explicitly==. Token from IMDS `169.254.169.254` (several UAMIs → `client_id`). Identity grants ==!nothing== until a role on the target. Token cache about 24 h. Deleted identity leaves role assignments as ==!Identity not found==. Up to 20 federated credentials. ==!No PIM, no CA== → narrow RBAC + access reviews.

## D1.2 Key Vault

Pages: [1.2.1](../objective/D1.2.1.html) deploy · [1.2.2](../objective/D1.2.2.html) settings · [1.2.3](../objective/D1.2.3.html) access · [1.2.4](../objective/D1.2.4.html) firewall · [1.2.5](../objective/D1.2.5.html) objects · [1.2.6](../objective/D1.2.6.html) secret scanning · [1.2.7](../objective/D1.2.7.html) Defender

| Container | Protection | Holds |
|---|---|---|
| Standard | Software, FIPS 140-2 L1 | Keys, secrets, certs |
| ==@Premium== | ==@FIPS 140-3 L3== HSM keys | Keys, secrets, certs |
| ==@Managed HSM== | FIPS 140-3 L3, single-tenant, local RBAC, customer security domain | ==!HSM keys only== |

| New-vault setting | Default | Rule |
|---|---|---|
| Soft delete | On, ==@90 days== (7–90) | Can't disable; days ==!fixed at creation== |
| Purge protection | Off | ==!Never off once on==; CMK services require it |
| Permission model | Azure RBAC (API `2026-02-01`+) | Older API versions retire 27 Feb 2027 |
| Public access | Enabled, firewall off | — |
| Diagnostics | Off | ==@AuditEvent== → `AzureDiagnostics` / `AZKVAuditLogs`, about 10 min |

Enabled-for switches: `enabledForDeployment` (VM certs), `enabledForTemplateDeployment` (ARM secrets), `enabledForDiskEncryption` (==@required for ADE==). Role-assignment changes are in the ==!Activity log, not AuditEvent==.

| | Azure RBAC | Access policy (legacy) |
|---|---|---|
| Planes | Control + data | Data only |
| Who grants data access | `roleAssignments/write` holders | ==!Anyone with `vaults/write` (Contributor)== |
| Scope | Down to one secret/key/cert | Whole vault |
| PIM / deny assignments | ==+Yes== | No |
| Limit | RBAC limits | 1,024 entries |

Switching to RBAC ==!invalidates all access policies at once== — assign roles first. Data roles work only on RBAC vaults.

**Network (D1.2.4).** Firewall = ==!data plane only== (ARM ignores it). IP rules: 1,000, public IPv4, ==!no RFC 1918, no IPv6==. VNet rules: 200, need `Microsoft.KeyVault` service endpoint. Full isolation = ==+private endpoint + `privatelink.vaultcore.azure.net` + Disable public access== (endpoint first). Trusted services bypass works with public disabled; ==!Azure DevOps not trusted==. NSP **Secure by perimeter** blocks even trusted services.

**Objects (D1.2.5).** Keys RSA/EC (+HSM); oct-HSM Premium preview. Rotation min ==@7 days==; keep old versions enabled. BYOK needs a KEK (RSA-HSM, `import` only). Secrets ≤25 KB; ==!expiry doesn't block get==. Key Vault references refresh within 24 h. Autorenew only self-signed and ==@DigiCert/GlobalSign==; other CAs → Merge Signed Request. Contacts ==!vault-wide==. HSM cert keys ==!never exportable==.

**Secret scanning (D1.2.6).** VM disks: ==+Defender CSPM or Servers Plan 2==. ARM/CloudFormation deployments: ==+Defender CSPM only==. Repos: GitHub Advanced Security. Agentless, every 24 h, 4 TB limit, one shared agentless toggle; ==!no alerts==. Fix = move to Key Vault ==+and rotate==.

**Defender for Key Vault (D1.2.7).** ==!Off by default, subscription-wide, no per-vault switch==. Alerts `KV_TORAccess`, `KV_SuspiciousIPAccess`, `KV_OperationVolumeAnomaly`, `KV_PutGetAnomaly`, `KV_ListGetAnomaly`, `KV_AppAnomaly`. Investigation history needs AuditEvent ==!already flowing==. Respond: firewall → remove access → rotate.

## D1.3 Governance

Pages: [1.3.1](../objective/D1.3.1.html) Policy · [1.3.2](../objective/D1.3.2.html) compliance · [1.3.3](../objective/D1.3.3.html) recommendations · [1.3.4](../objective/D1.3.4.html) locks · [1.3.5](../objective/D1.3.5.html) roles · [1.3.6](../objective/D1.3.6.html) custom roles · [1.3.7](../objective/D1.3.7.html) overprivilege · [1.3.8](../objective/D1.3.8.html) Backup · [1.3.9](../objective/D1.3.9.html) IaC

| Need | Policy effect |
|---|---|
| Block create/update | `deny` (==!never fixes existing==) |
| Block DELETE | `denyAction` |
| Report | `audit`; related resource → `auditIfNotExists` |
| Fix existing | ==+`modify` / `deployIfNotExists` + remediation task== (identity needs `roleDefinitionIds` roles) |

- Order: disabled → append/modify → deny → audit → manual → auditIfNotExists → denyAction; after success AINE/DINE.
- Mode ==@All== (RGs, subscriptions) vs ==@Indexed== (tags + location types).
- `DoNotEnforce` = evaluate and report, no effect ≠ effect `disabled`.
- **Exclusion** (`notScopes`) = not evaluated. **Exemption** = counted Exempt, ==@Waiver== or ==@Mitigated==, one assignment.
- Cumulative most restrictive; ==!RBAC never overrides deny==. Definition location limits assignment scope.
- Timing: 5 min to apply, 15 min per change, 24 h cycle; `az policy state trigger-scan`. Remediation 500 resources (max 50,000), 10 parallel.

**Compliance (D1.3.2).** ==@MCSB== is default (AWS/GCP add their own). Extra standards need a paid plan ==!other than Servers P1 / APIs P1==. Standard = policy initiative. Grey = ==+manual attestation==. Assessments about 12 h. Download report (your evidence) vs Audit reports (Microsoft's certificates).

**Recommendations (D1.3.3).** Audit / Disabled / ==@Deny== (block new) / ==@Enforce== (DINE at creation) — Azure only. Custom KQL recommendation needs ==!Defender CSPM==. Governance rules: owner by tag/email, 7/14/30/90 days. Exemption ==+Mitigated → healthy, score up==; ==@Waiver → neutral==; up to 24 h, 5,000 per subscription.

**Locks (D1.3.4).** Delete = `CanNotDelete`; Read-only = `ReadOnly`. Control plane only (==!blobs still deletable==). Inherited; ==!no management-group locks==. ReadOnly blocks POST: ==!list storage keys, start VMs==. CanNotDelete blocks deleting role assignments, 800-deployment cap, Backup restore-point RG cleanup.

**Roles (D1.3.5–1.3.7).** Contributor ==!can't assign roles or write policy==. RBAC Administrator = assignments only, ==+not policy==; add a **condition** to constrain roles/principals. Limits: 5,000 per subscription, 500 per management group; eligible don't count. Owner/Contributor have ==!no DataActions==. Global Administrator ≠ Azure Owner.

| Custom role | Azure | Entra |
|---|---|---|
| Controls | Resources (`Actions`, `DataActions`) | Directory (`microsoft.directory/…`) |
| Scope | `AssignableScopes`: ==!no `/`, one MG max, DataActions not at MG== | Tenant, AU, single object |
| Limit | 5,000/tenant, 2,000 scopes | 100/org |
| Licence | None | ==@P1== |
| Clone built-in | Yes | ==!No== |

`NotActions` ==!is not a deny==. CIEM (Defender CSPM only): inactive = unused assignments over ==@90 days== (since 2 Feb 2026). Max ==@3== subscription owners. Access review denial ==!doesn't remove group membership==.

**Backup (D1.3.8).** Soft delete 14–180 days, default 14 (first 14 free); always-on = irreversible. Immutable: Disabled → Enabled → ==!Locked (irreversible, WORM, blocks subscription cancellation)==. MUA: Resource Guard ==+same region, other subscription/tenant==; Restore protection ==!off by default==. CMK: ==!new vault only, no return to PMK==. Excellent = Locked/always-on ==+and== MUA.

**IaC (D1.3.9).** MSDO `microsoft/security-devops-action` / `MicrosoftSecurityDevOps@1`, `categories: 'IaC'`. Template Analyzer = ARM/Bicep; ==@Checkov== = Terraform too. Agentless code scanning: 8 h discovery, daily, under 1 GB. PR annotations need ==!Defender CSPM== (+GHAS on GitHub). ==+Policy deny== blocks every path. EPAC = ==!open source==. `@secure()` keeps parameters out of history.

## Traps → truth

- Order CA policies → ==!no order==; block wins.
- PIM or CA on a managed identity → ==!neither==; narrow RBAC + reviews.
- Authenticator push is phishing-resistant → ==!no==.
- Contributor can't read secrets → ==!unless access-policy model==; switch to RBAC.
- Firewall blocks ARM deployments → ==!no==, data plane only.
- Reduce soft-delete days / disable purge protection → ==!impossible==.
- Lock stops purge of keys → ==!no==; purge protection does.
- Deny fixes existing resources → ==!no==; modify/DINE + remediation.
- Remediation task on Audit/Deny built-ins → ==!not possible==.
- Child Audit cancels parent Deny → ==!no==.
- Lock on management group → ==!impossible==; policy deploys locks or `denyAction`.
- `NotActions` denies → ==!no==; use deny assignments.
- Security Reader sees compliance → ==!no==, Reader.
- Waiver raises score → ==!no==, Mitigated does.
- Defender for Key Vault per vault → ==!no==, per subscription.
- Expired secret blocks reads → ==!no==; disable the version.
- Revoke user consent in the portal → ==!no==, Graph/PowerShell.
- CMK on an existing backup vault → ==!no==, new vault.
- Break-glass accounts in PIM → ==!no==; two permanent active GAs, excluded from CA.
- Firewall-blocked portal can't list secrets → network, ==!not RBAC==.
- Secrets scanning raises alerts → ==!no==, posture findings only.
- Backup admin with Contributor on the Resource Guard → ==!can self-approve==; Reader only.
